# PostgreSQL 表设计

## 核心规则

- **定义主键 (PRIMARY KEY)**：参考表（如 users, orders 等）必须定义主键。时间序列/事件/日志数据不一定需要。使用主键时，优先选择 `bigint generated always as identity`；仅在需要全局唯一性/不透明性时使用 `uuid`。
- **优先范式化 (3NF)**：消除数据冗余和更新异常；**仅**在经过测量的、高 ROI 的读取场景且连接性能已被证明存在问题时，才进行反范式化。过早的反范式化会增加维护负担。
- **语义必须时添加 NOT NULL**：在语义需要的地方添加 `not null`；对常见值使用 `default`。
- **为你实际查询的路径创建索引**：PK/唯一键（自动创建），**外键列（禁止创建！）**，频繁过滤/排序的列，以及连接键。
- **类型选择**：根据字段存储的**实际数据内容**选择合适的 PostgreSQL 数据类型。

## PostgreSQL 避坑指南

- **标识符**：未加引号 → 自动转为小写。避免使用加引号/混合大小写的名称。约定：表名/列名使用 `snake_case`（蛇形命名法）。
- **唯一性 + NULL**：UNIQUE 允许存在多个 NULL。使用 `unique (...) nulls not distinct` (PG15+) 来限制只能有一个 NULL。
- **外键索引**：PostgreSQL **不会**自动为外键列创建索引。请手动添加。
- **无静默强制转换**：长度/精度溢出会报错（不会截断）。例如：向 `numeric(2,0)` 插入 999 会失败报错，不像某些数据库会静默截断或四舍五入。
- **序列/标识列存在间隙**（正常现象；不要试图“修复”）。回滚、崩溃和并发事务都会导致 ID 序列产生间隙（1, 2, 5, 6...）。这是预期行为——不要试图让 ID 连续。
- **堆存储**：默认没有聚簇主键（不像 SQL Server/MySQL InnoDB）；`cluster` 是一次性重组，后续插入不会维护顺序。除非显式聚簇，否则磁盘上的行顺序即为插入顺序。
- **MVCC**：更新/删除会留下死元组（dead tuples）；vacuum 会处理它们——设计时应避免宽行的频繁更新（hot wide-row churn）。
- **格式化**：给出的sql语句**必须**是全关键字**小写**；

## 数据类型

- **ID**：首选 `bigint generated always as identity`（`generated by default` 也可以）；在合并/联合/分布式系统中使用或需要不透明 ID 时使用 `uuid`。生成方式：`uuidv7()`（PG18+ 首选）或 `gen_random_uuid()`（旧版本）。
- **整数**：除非存储空间极度紧张，否则首选 `bigint`；小范围数值用 `integer`；除非受限否则避免使用 `smallint`。
- **浮点数**：除非存储空间极度紧张，否则首选 `double precision` 而非 `real`。精确小数运算使用 `numeric`。
- **字符串**：首选 `text`；如果需要长度限制，使用 `check (length(col) <= n)` 代替 `varchar(n)`；避免使用 `char(n)`。二进制数据使用 `bytea`。大字符串/二进制数据（默认 >2KB 阈值）会自动使用 TOAST 压缩存储。TOAST 策略：`plain`（无 TOAST），`extended`（压缩 + 行外），`external`（行外，不压缩），`main`（压缩，尽可能行内）。默认 `extended` 通常是最佳选择。通过 `alter table tbl alter column col set storage strategy` 控制，通过 `alter table tbl set (toast_tuple_target = 4096)` 设置阈值。大小写不敏感：区域/重音处理使用非确定性排序规则（non-deterministic collations）；纯 ASCII 使用 `lower(col)` 表达式索引（首选，除非列需要大小写不敏感的 PK/FK/UNIQUE）或 `citext`。
- **金额**：`numeric(p,s)`（绝不要用 float）。
- **时间**：时间戳用 `timestamptz`；仅日期用 `date`；时长用 `interval`。避免使用 `timestamp`（无时区）。事务开始时间用 `now()`，当前挂钟时间用 `clock_timestamp()`。
- **布尔值**：使用带 `not null` 约束的 `boolean`，除非需要三态值。
- **枚举**：对于小的、稳定的集合（如美国州名、星期几）使用 `create type ... as enum`。对于业务逻辑驱动且会演变的值（如订单状态）→ 使用 TEXT (或 INT) + CHECK 或查找表。
- **数组**：`text[]`, `integer[]` 等。用于查询元素的有序列表。使用 **GIN** 索引进行包含 (`@>`, `<@`) 和重叠 (`&&`) 查询。访问：`arr[1]`（1-based 索引），`arr[1:3]`（切片）。适用于标签、分类；避免用于关系——应使用关联表。字面量语法：`'{val1,val2}'` 或 `array[val1,val2]`。
- **范围类型**：`daterange`, `numrange`, `tstzrange` 用于区间。支持重叠 (`&&`)、包含 (`@>`)、运算符。使用 **GiST** 索引。适用于调度、版本控制、数值范围。选择一种边界方案并保持一致；默认首选 `[)`（包含/不包含）。
- **网络类型**：IP 地址用 `inet`，网络范围用 `cidr`，MAC 地址用 `macaddr`。支持网络运算符 (`<<`, `>>`, `&&`)。
- **几何类型**：`point`, `line`, `polygon`, `circle` 用于 2D 空间数据。使用 **GiST** 索引。高级空间特性考虑使用 **PostGIS**。
- **全文搜索**：`tsvector` 用于文档，`tsquery` 用于查询。对 `tsvector` 使用 **GIN** 索引。务必指定语言：`to_tsvector('english', col)` 和 `to_tsquery('english', 'query')`。切勿使用单参数版本。这也适用于索引表达式和查询。
- **域类型**：`create domain email as text check (value ~ '^[^@]+@[^@]+$')` 用于带验证的可重用自定义类型。在表之间强制执行约束。
- **复合类型**：`create type address as (street text, city text, zip text)` 用于列内的结构化数据。使用 `(col).field` 语法访问。
- **JSONB**：优于 JSON；使用 **GIN** 索引。仅用于可选/半结构化属性。**仅当**必须保留内容的原始顺序时才使用 JSON。
- **向量类型**：`pgvector` 提供的 `vector` 类型，用于嵌入向量相似度搜索。

### 请勿使用以下数据类型

- **不要**使用 `timestamp`（无时区）；**请**使用 `timestamptz`。
- **不要**使用 `money` 类型；**请**使用 `numeric`。
- **不要**使用 `timetz` 类型；**请**使用 `timestamptz`。
- **不要**使用 `timestamptz(0)` 或其他精度规范；**请**使用 `timestamptz`。
- **不要**使用 `serial` 类型；**请**使用 `generated always as identity`。

## 表类型

- **常规表 (Regular)**：默认；完全持久化，有日志。
- **临时表 (TEMPORARY)**：会话级，自动删除，无日志。用于草稿工作更快。
- **不记录日志表 (UNLOGGED)**：持久化但不抗崩溃。写入更快；适用于缓存/暂存。

## 行级安全 (Row-Level Security)

使用 `alter table tbl enable row level security` 启用。创建策略：`create policy user_access on orders for select to app_users using (user_id = current_user_id())`。内置的行级用户访问控制。

## 约束

- **PK**：隐式 UNIQUE + NOT NULL；创建 B-tree 索引。
- **FK**：指定 `on delete/update` 动作 (`cascade`, `restrict`, `set null`, `set default`)。在引用列上添加显式索引——加速连接并防止父级删除/更新时的锁定问题。对于事务结束时检查的循环 FK 依赖，使用 `deferrable initially deferred`。
- **UNIQUE**：创建 B-tree 索引；允许多个 NULL，除非使用 `nulls not distinct` (PG15+)。标准行为：`(1, NULL)` 和 `(1, NULL)` 是允许的。使用 `nulls not distinct`：只允许一个 `(1, NULL)`。除非确实需要重复 NULL，否则首选 `nulls not distinct`。
- **CHECK**：行级约束；NULL 值通过检查（三值逻辑）。例如：`check (price > 0)` 允许 NULL 价格。结合 `not null` 强制执行：`price numeric not null check (price > 0)`。
- **EXCLUDE**：使用运算符防止重叠值。`exclude using gist (room_id with =, booking_period with &&)` 防止房间重复预订。需要适当的索引类型（通常是 GiST）。

## 索引

- **B-tree**：默认，用于等值/范围查询 (`=`, `<`, `>`, `between`, `order by`)。
- **复合索引**：顺序很重要——如果最左前缀有等值查询，则使用索引（`where a = ? and b > ?` 使用 `(a,b)` 索引，但 `where b = ?` 不使用）。将选择性最强/过滤最频繁的列放在前面。
- **覆盖索引**：`create index on tbl (id) include (name, email)` - 包含非键列，进行仅索引扫描（Index-Only Scan），无需访问表堆。
- **部分索引**：用于热点子集（`where status = 'active'` → `create index on tbl (user_id) where status = 'active'`）。任何带有 `status = 'active'` 的查询都可以使用此索引。
- **表达式索引**：用于计算搜索键（`create index on tbl (lower(email))`）。表达式必须与 WHERE 子句完全匹配：`where lower(email) = 'user@example.com'`。
- **GIN**：JSONB 包含/存在，数组 (`@>`, `?`)，全文搜索 (`@@`)。
- **GiST**：范围，几何，排除约束。
- **BRIN**：非常大、自然有序的数据（时间序列）——存储开销极小。当磁盘上的行顺序与索引列相关（插入顺序或 `cluster` 后）时有效。

## 分区

- 用于非常大的表（>1 亿行），查询始终根据分区键（通常是时间/日期）进行过滤。
- 替代用途：用于数据维护任务（如定期修剪或批量替换数据）的表。
- **RANGE**：常见于时间序列 (`partition by range (created_at)`)。创建分区：`create table logs_2024_01 partition of logs for values from ('2024-01-01') to ('2024-02-01')`。**TimescaleDB** 自动化了基于时间或 ID 的分区，并提供保留策略和压缩。
- **LIST**：用于离散值 (`partition by list (region)`)。例如：`for values in ('us-east', 'us-west')`。
- **HASH**：用于无自然键时的均匀分布 (`partition by hash (user_id)`)。使用模数创建 N 个分区。
- **约束排除**：要求分区上有 `check` 约束以便查询规划器修剪。声明式分区（PG10+）会自动创建。
- 优先使用声明式分区或 hypertables。**不要**使用表继承。
- **限制**：无全局 UNIQUE 约束——必须在 PK/UNIQUE 中包含分区键。不支持指向分区表的外键；需使用触发器。

## 特殊考量

### 更新密集型表 (Update-Heavy Tables)

- **分离冷热列**——将频繁更新的列放入单独的表，以尽量减少膨胀。
- **使用 `fillfactor=90`** 为 HOT 更新留出空间，避免索引维护。
- **避免更新索引列**——防止有益的 HOT 更新失效。
- **按更新模式分区**——将频繁更新的行与稳定数据分到不同分区。

### 插入密集型工作负载 (Insert-Heavy Workloads)

- **最小化索引**——只创建查询需要的；每个索引都会减慢插入速度。
- **使用 `COPY` 或多行 `INSERT`** 代替单行插入。
- **UNLOGGED 表**用于可重建的暂存数据——写入快得多。
- **推迟索引创建**用于批量加载——>删除索引，加载数据，重建索引。
- **按时间/哈希分区**以分散负载。**TimescaleDB** 自动化了插入密集型数据的分区和压缩。
- **使用自然键作为主键**，如 (timestamp, device_id)，如果强制全局唯一性很重要；许多插入密集型表根本不需要主键。
- 如果确实需要代理键，**优先使用 `bigint generated always as identity` 而非 `uuid`**。

### 友好支持 Upsert 的设计 (Upsert-Friendly Design)

- **需要 UNIQUE 索引**在冲突目标列上——`on conflict (col1, col2)` 需要精确匹配的唯一索引（部分索引无效）。
- **使用 `excluded.column`** 引用将要插入的值；只更新实际变更的列以减少写入开销。
- 当不需要实际更新时，**`do nothing` 比 `do update` 更快**。

### 安全的架构演进 (Safe Schema Evolution)

- **事务性 DDL**：大多数 DDL 操作可以在事务中运行并回滚——`begin; alter table...; rollback;` 用于安全测试。
- **并发索引创建**：`create index concurrently` 避免阻塞写入，但不能在事务中运行。
- **易变默认值导致重写**：添加带有易变默认值（如 `now()`, `gen_random_uuid()`）的 `not null` 列会重写整个表。非易变默认值很快。
- **先删除约束再删除列**：`alter table drop constraint` 然后 `drop column` 以避免依赖问题。
- **函数签名变更**：`create or replace` 带不同参数会创建重载，而不是替换。如果不需要重载，请先 DROP 旧版本。

## 生成列

- `... generated always as (<expr>) stored` 用于计算的、可索引的字段。PG18+ 增加了 `virtual` 列（读取时计算，不存储）。

## 扩展

- **`pgcrypto`**：`crypt()` 用于密码哈希。
- **`uuid-ossp`**：替代的 UUID 函数；新项目首选 `pgcrypto`。
- **`pg_trgm`**：使用 `%` 运算符、`similarity()` 函数进行模糊文本搜索。配合 GIN 索引加速 `like '%pattern%'`。
- **`citext`**：大小写不敏感的文本类型。除非需要大小写不敏感的约束，否则首选 `lower(col)` 表达式索引。
- **`btree_gin`/`btree_gist`**：启用混合类型索引（例如，在 JSONB 和文本列上同时使用 GIN 索引）。
- **`hstore`**：键值对；大部分被 JSONB 取代，但用于简单的字符串映射仍有用。
- **`timescaledb`**：时间序列必备——自动分区、保留、压缩、连续聚合。
- **`postgis`**：超越基本几何类型的全面地理空间支持——基于位置的应用必备。
- **`pgvector`**：用于嵌入向量相似度搜索的向量搜索。
- **`pgaudit`**：所有数据库活动的审计日志。

## JSONB 使用指南

- 首选 **GIN** 索引的 `jsonb`。
- 默认：`create index on tbl using gin (jsonb_col);` → 加速：
  - **包含** `jsonb_col @> '{"k":"v"}'`
  - **键存在** `jsonb_col ? 'k'`, **任意/所有键** `?|`, `?&`
  - 嵌套文档上的 **路径包含**
  - **析取** `jsonb_col @> any(array['{"status":"active"}', '{"status":"pending"}'])`
- 重度 `@>` 工作负载：考虑 opclass `jsonb_path_ops` 用于更小/更快的仅包含索引：
  - `create index on tbl using gin (jsonb_col jsonb_path_ops);`
  - **权衡**：失去对键存在 (`?`, `?|`, `?&`) 查询的支持——仅支持包含 (`@>`)
- 特定标量字段的等值/范围：提取并使用 B-tree 索引（生成列或表达式）：
  - `alter table tbl add column price int generated always as ((jsonb_col->>'price')::int) stored;`
  - `create index on tbl (price);`
  - 优先使用 `where price between 100 and 500`（使用 B-tree）而非不带索引的 `where (jsonb_col->>'price')::int between 100 and 500`。
- JSONB 内的数组：使用 GIN + `@>` 进行包含查询（如标签）。如果只做包含查询，考虑 `jsonb_path_ops`。
- 将核心关系保留在表中；使用 JSONB 存储可选/可变属性。
- 使用约束限制列中允许的 JSONB 值，例如 `config jsonb not null check(jsonb_typeof(config) = 'object')`

## 示例

### 用户 (Users)

```sql
create table users (
  user_id bigint generated always as identity primary key,
  email text not null unique,
  name text not null,
  created_at timestamptz not null default now()
);
create unique index on users (lower(email));
create index on users (created_at);
```

### 订单 (Orders)

```sql
create table orders (
  order_id bigint generated always as identity primary key,
  user_id bigint not null references users(user_id),
  status text not null default 'PENDING' check (status in ('PENDING','PAID','CANCELED')),
  total numeric(10,2) not null check (total > 0),
  created_at timestamptz not null default now()
);
create index on orders (user_id);
create index on orders (created_at);
```

### JSONB

```sql
create table profiles (
  user_id bigint primary key references users(user_id),
  attrs jsonb not null default '{}',
  theme text generated always as (attrs->>'theme') stored
);
create index profiles_attrs_gin on profiles using gin (attrs);
```
