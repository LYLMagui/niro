# 智能调度系统重构计划

针对您遇到的“任务间隔失效”与“风控触发”问题，经过代码分析，我们定位到核心原因在于调度策略选择不当以及循环机制的缺失。我们将通过以下方案进行修复：

## 1. 核心问题修复 (Anti-Ban)
- **现状**：当前使用 `scheduleAtFixedRate`（固定速率）。如果任务发生阻塞或网络波动，为了追赶进度，后续任务会瞬间连续执行，直接导致 IP 被封。
- **修复**：全局替换为 **`scheduleWithFixedDelay`**（固定延迟）。
  - **效果**：确保上一次任务**彻底结束**后，必须等待完整的 10秒（或其他配置间隔），才允许发起下一次请求。这是规避风控的物理底线。

## 2. 智能调度逻辑增强 (Smart Loop)
我们将实现“工作-休息-循环”的完整生命周期：

### 场景 A：Cron 定时模式 (现有增强)
- **逻辑**：到达 Cron 时间点 -> 启动任务 -> 持续运行 `Duration` (如10分钟) -> **自动停止** -> 等待下一次 Cron 触发。
- **改动**：优化 `stopSession` 逻辑，确保会话结束时只清理当前执行线程，保留 Cron 监听器。

### 场景 B：立即执行 + 循环模式 (新增特性)
- **逻辑**：立即启动 -> 持续运行 `Duration` -> **进入休眠 (`RestPeriod`)** -> 休眠结束自动重启 -> 循环...
- **实现**：在任务达到 `Duration` 限制时，检查是否有配置 `RestPeriod`。若有，则注册一个单次延时任务在 X 分钟后重新唤醒 `startSession`。

## 3. 执行步骤
1.  **后端重构 (`C5TaskScheduler.java`)**：
    -   将 `FixedRate` 改为 `FixedDelay`。
    -   实现 `restPeriod` 的休眠唤醒逻辑。
    -   增加详细的调度日志（显示下次唤醒时间）。
2.  **编译验证**：
    -   执行 `mvn clean package` 确保代码无误。
3.  **前端确认**：
    -   确认前端 `TaskConfig.vue` 已包含 `restPeriod` (休息时长) 的配置入口（经查阅已存在，无需修改）。

该方案将完全解决“无间隔”问题，并支持您期望的“运行10分钟、休息、再运行”的智能托管需求。
