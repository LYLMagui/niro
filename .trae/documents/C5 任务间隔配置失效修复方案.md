# C5 任务间隔配置失效修复计划

## 问题根源分析
您配置了 20s 间隔却执行 10s，原因在于**前端数据同步机制存在逻辑漏洞**，导致后端接收到的参数与您的配置不符：
1.  **随机模式失效**：前端目前的逻辑会强制将 `scanInterval`（固定间隔字段）设置为 `Min` 值。由于后端优先使用固定间隔字段，导致“随机范围”配置（如 10s-20s）永远被忽略，只能以最小间隔（10s）运行。
2.  **编辑时脏数据**：在编辑任务时，如果数据库中存有旧的 `scanInterval` 值（如 10），而 UI 初始化时未能正确触发同步逻辑将其清除，后端就会继续使用这个旧值，无视您在 UI 上新设置的范围。

## 修复方案
我们需要在前端 `TaskConfig.vue` 中建立严格的数据互斥同步机制，确保“所见即所得”。

### 具体步骤
1.  **重构同步逻辑 (`TaskConfig.vue`)**：
    -   提取 `syncFromUiState` 函数。
    -   **逻辑修正**：仅当 `Min == Max`（固定间隔）时，才设置 `scanInterval`。
    -   **互斥清除**：当 `Min != Max`（随机范围）时，强制将 `scanInterval` 置为 `undefined`，迫使后端使用随机调度逻辑。

2.  **强制初始化**：
    -   在 `handleEdit`（打开编辑窗口）时，强制调用一次 `syncFromUiState`。
    -   这确保了无论数据库中存储了什么旧数据，提交时都会完全以当前 UI 上的配置为准。

### 预期效果
-   **固定间隔**：设置 20s-20s -> 实际运行 20s（FixedDelay）。
-   **随机间隔**：设置 10s-20s -> 实际运行 10s~20s 之间的随机值。
-   **彻底修复**：配置 20s 却跑 10s 的诡异现象将不再出现。
