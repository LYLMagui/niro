# Niro 工程提效与质量军规

## 1. 任务前置思考 (Triple-Check)
- **多维评估**：在任何方案实施前，必须输出 [架构视角] (稳定性/扩展性)、[产品视角] (业务闭环/风控防护)、[用户视角] (易用性)。
- **勇敢质疑**：若需求会导致 Buff 封号、数据不一致或超卖风险，必须先指出风险并提出修正建议，严禁盲目执行。

## 2. 版本管理 (SemVer Release)
- **触发条件**：仅在“任务完成并要求提交”时操作 `docs/release.md`。
- **记录规范**：使用中文。禁止记录文件路径，仅记录功能增量或 Bug 修复。
- **版本号逻辑**：
  - Patch (0.0.x): 修复 Bug。
  - Minor (0.x.0): 新增扫货策略、新平台接入等功能。
  - Major (x.0.0): 架构重构（如引入虚拟线程、更换中间件）。

## 3. 数据库安全与规约 (SQL Standard)
- **关键字小写**：所有 SQL 关键字（select, from, where）必须全小写。
- **字段规范**：每个字段必须包含 `comment` 注释，必须设置 `default` 默认值。
- **索引意识**：针对查询条件字段，必须主动添加 `index`。
- **操作红线**：禁止调用任何工具自动执行 SQL。必须以代码块形式展示 SQL，并提示：`-- 请手动在数据库终端执行以下语句`。

## 4. 实时上下文同步
- **规则读取**：每次回复前，必须静默检索根目录下的所有 `.md` 规则文件及 `.traerules`，确保逻辑不偏离既定轨道。
