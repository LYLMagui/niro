# 购买统计页设计

## 技术规格
Goal: 将当前 `niro-client/src/views/InventoryBoard.vue` 从库存看板改为购买统计页，用于查看指定时间范围内的购买汇总、双折线趋势和按商品聚合的购买明细。
Scope: 本次设计覆盖页面定位、前端布局、统计口径、接口拆分策略、空态与容错策略；不覆盖具体代码实现细节和后端 SQL 实现。
Risks: 统计口径不统一会导致卡片、趋势图、表格数据互相对不上；页面改造后若仍复用库存批次 DTO，结构会继续别扭；多接口并行后若没有独立空态，仍然会出现局部失败拖垮整体体验的问题。
Compatibility: 直接替换当前页面定位，但保持现有页面入口不变；统计对象限定为成功购买订单；失败区块静默占位，不影响其他区块展示；商品图片缺失使用默认占位图。
Verification: 先完成静态页面布局确认；实现阶段验证筛选、卡片、趋势图、表格、空态、局部失败、默认占位图、类型检查与构建。

## 背景与问题

当前 `niro-client/src/views/InventoryBoard.vue` 展示的是库存批次视角：按商品名 + 单价 + 购买日期聚合，强调库存数量、库存金额和批量成本计算。这和本次真实目标不一致。

本次真实需求是购买统计视角，核心问题是：

- 某个时间范围内总共买了多少钱
- 买了多少件
- 平均买入单价是多少
- 每天的购买金额和购买件数怎么变化
- 哪些商品买得最多、花费最高

所以这次不再保留“库存看板”的问题定义，而是直接改成“购买统计页”。

## 需求结论

用户已确认以下业务口径：

1. 直接替换当前页面，不保留库存看板模式。
2. 页面上半部分看时间维度统计，下半部分看按商品聚合的明细。
3. 时间范围支持：本日、本周、本月、自定义日期范围。
4. 明细表按商品名聚合，不按日期、不按价格拆分。
5. 平均单价使用加权平均：总金额 ÷ 总件数。
6. 趋势图使用双折线：购买金额 + 购买件数。
7. 后端采用多接口分区请求，不做单接口大而全返回。
8. 某个区块接口失败时采用静默占位，不弹强提示。
9. 无数据或无图片时要有默认占位组件或占位图。
10. 商品明细表增加“购买金额占比”列。

## 方案对比

### 方案 A：单接口返回整页统计结果

做法：

- 一个接口同时返回 summary、trend、items
- 前端只请求一次，再把三个区域一起渲染

优点：

- 数据口径最统一
- 前端实现最简单
- 状态管理最轻

缺点：

- 一个接口异常会拖死整页
- 和用户要求的“分区失败不影响全页”目标冲突
- 后端返回结构过重，演进不够灵活

### 方案 B（采用）：多接口分区动态请求

做法：

- 汇总卡片独立接口
- 趋势图独立接口
- 商品明细表独立接口
- 每个区域独立 loading / empty / error fallback

优点：

- 某个接口异常不会导致整页无数据
- 页面容错更符合统计页使用场景
- 后续可以单独优化某个区块，不影响其他区块

缺点：

- 前端状态处理更多
- 必须明确保证三个接口统计口径一致

### 方案 C：继续沿用库存接口，前端二次计算统计结果

做法：

- 前端继续调用现有库存看板接口
- 在浏览器里再去算卡片、趋势图和商品聚合表

优点：

- 后端改动最少

缺点：

- 数据结构方向错误，前端会堆补丁
- 趋势图和商品维度统计都不自然
- 页面语义继续混乱

## 结论

采用 **方案 B**。

原因很简单：当前问题不是“接口少”，而是“容错目标变了、页面语义也变了”。购买统计页天然应该分区渲染，各区块独立请求、独立占位，才能避免一个接口异常时整页白板。

## 详细设计

### 1. 页面定位

页面仍然使用当前入口和路由，但业务定义改为“购买统计页”。

页面职责：

- 展示指定时间范围内的购买汇总
- 展示按天变化的购买趋势
- 展示按商品聚合后的购买明细

页面不再承担以下职责：

- 库存批次查看
- 批量成本计算
- 库存备注维护

这三类能力不属于本次页面目标，不应继续保留在同一页面里混淆语义。

### 2. 页面布局

页面分为四个主要区域：

#### 2.1 筛选区

筛选区放在页面顶部，字段如下：

- 商品关键词
- 本日 / 本周 / 本月快捷范围
- 自定义日期范围
- 查询按钮
- 重置按钮

交互规则：

- 点击快捷范围时，自动同步日期范围状态
- 使用自定义日期范围时，快捷范围高亮取消
- 查询时只刷新对应统计区块的数据
- 重置时恢复默认筛选状态

默认建议：

- 首次进入页面默认选中“本日”

#### 2.2 汇总卡片区

展示 4 张卡片：

1. 购买总金额
2. 购买总件数
3. 平均单价
4. 商品种类数

要求：

- 四张卡片视觉权重高于表格
- 数值是当前筛选条件下的结果，不暗示全局累计
- 卡片区接口失败时，直接显示默认空值或空态，不弹错误提示

#### 2.3 趋势图区

趋势图区位于卡片下方，使用双折线：

- 折线 1：购买金额
- 折线 2：购买件数

正式实现建议：

- 使用 `ECharts + vue-echarts`

原因：

- 当前项目未引入图表库
- ECharts 对双折线、tooltip、legend、grid、空态处理更成熟
- 后续如果增加周/月维度、缩放、导出，也更顺手

展示规则：

- 默认按天展示
- 本日范围下，如果数据粒度仍按天，则图上可只显示 1 个点；若后续需要增强，可单独扩展为按小时，但这不在本次范围内
- 趋势图接口失败时，图表区域显示默认空态组件，不影响卡片和表格

#### 2.4 商品明细表

表格位于趋势图下方，按商品名聚合。

列定义：

- 商品信息
- 购买件数
- 购买总金额
- 平均单价
- 购买金额占比
- 最近购买日期

列说明：

##### 商品信息

显示：

- 商品图片
- 商品名称
- 必要时可增加弱化的次信息，但本次不强制

图片策略：

- 商品图缺失或加载失败时使用默认占位图

##### 购买件数

显示当前筛选范围内该商品的成功购买总件数。

##### 购买总金额

显示当前筛选范围内该商品购买总金额。

##### 平均单价

计算方式固定为：

- `总金额 ÷ 总件数`

##### 购买金额占比

计算方式：

- `该商品购买总金额 ÷ 当前筛选范围内全部商品购买总金额`

显示建议：

- 百分比展示，保留 2 位小数

##### 最近购买日期

显示该商品在当前筛选范围内最后一次成功购买日期。

### 3. 后端接口拆分

后端采用多接口并行方案。

#### 3.1 汇总卡片接口

返回字段建议：

- `totalAmount`
- `totalQuantity`
- `avgPrice`
- `goodsTypeCount`

职责：

- 只负责卡片区，不混入趋势或表格数据

#### 3.2 趋势图接口

返回字段建议：

- `date`
- `amount`
- `quantity`

职责：

- 只提供双折线时间序列数据
- 数据粒度本次固定按天

#### 3.3 商品明细表接口

返回字段建议：

- `goodsName`
- `goodsImg`
- `totalQuantity`
- `totalAmount`
- `avgPrice`
- `amountRatio`
- `latestPurchaseDate`

职责：

- 只负责表格区数据

### 4. 统计口径

所有接口必须共享同一套基础筛选条件和统计边界。

#### 4.1 统计对象

只统计“成功购买订单”。

#### 4.2 筛选条件

统一接受：

- 商品关键词
- 开始日期
- 结束日期

#### 4.3 聚合规则

- 卡片：对筛选结果整体汇总
- 趋势图：按天汇总
- 表格：按商品名汇总

#### 4.4 平均单价

统一使用：

- `总金额 ÷ 总件数`

不允许某个区块自己改成普通平均，否则口径会冲突。

### 5. 页面状态与容错

每个区块独立处理以下状态：

- loading
- empty
- fallback

#### 5.1 loading

- 卡片区、趋势图区、表格区可以分别进入 loading
- 不要求全屏 loading

#### 5.2 empty

- 查询结果为空时，各区块显示空态组件
- 空态文案要直接表达“暂无购买统计数据”或同类含义

#### 5.3 fallback

- 某个接口失败时，静默显示该区块的空态或默认占位
- 不使用强提示弹窗打断操作
- 页面其他区块正常显示

#### 5.4 默认占位图

- 商品图缺失时显示默认占位图
- 占位图风格应与当前后台风格一致，避免突兀

### 6. 静态原型方向

用户已确认先看静态 HTML 布局效果，再进入实现阶段。

当前静态原型方向已经确认：

- 顶部筛选区
- 中部 4 张汇总卡片
- 折线趋势图
- 下方商品明细表

趋势图区静态版已经改成折线图视觉方案，正式实现时替换为图表组件即可。

### 7. 实现边界

本次设计明确不处理以下内容：

- 不保留库存批次视角
- 不保留批量成本计算
- 不保留库存备注编辑
- 不设计后端 SQL 细节
- 不扩展小时级趋势图
- 不额外加入导出、排行筛选、分平台分组等增强能力

原因：

- 这些内容不是当前核心问题
- 先把“购买统计”这件事做对，再考虑扩展

## 验证方案

### 1. 视觉验证

- 静态页面确认布局层级是否符合预期
- 卡片、趋势图、表格之间的视觉节奏是否顺
- 商品占位图和空态样式是否自然

### 2. 交互验证

- 本日 / 本周 / 本月 / 自定义切换是否正确
- 查询 / 重置是否只刷新对应数据
- 趋势图和表格是否随着筛选同步变化

### 3. 容错验证

- 卡片接口失败时，趋势图和表格仍可正常显示
- 趋势图接口失败时，卡片和表格仍可正常显示
- 表格接口失败时，卡片和趋势图仍可正常显示
- 商品图片缺失时能否显示默认占位图

### 4. 工程验证

- 前端通过 `pnpm type-check`
- 如环境允许，再执行 `pnpm build`
