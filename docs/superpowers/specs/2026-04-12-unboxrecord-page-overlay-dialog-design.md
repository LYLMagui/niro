# UnboxRecord 页内覆盖弹窗改造设计

日期：2026-04-12  
文件：`niro-client/src/views/UnboxRecord.vue`

## 1. 目标

将“新增批次 / 编辑批次”弹窗从“挂在 `PageFrame` 内层滚动 body 上的超大 dialog”，改成“覆盖当前路由页整个内容区的页内覆盖弹窗”。

核心目标：

- 打开弹窗后，覆盖 `UnboxRecord` 当前路由页整个内容区
- 不覆盖左侧菜单、顶部导航或浏览器全局视口
- 消除当前右侧贯穿式大空白问题
- 保持现有批次编辑器的业务逻辑、按钮行为、表格结构和保存链路不变
- 提升浏览器缩放时的布局稳定性

## 2. 范围

本次只调整 `UnboxRecord.vue` 中批次编辑器弹窗的宿主层级与滚动层级：

- 弹窗 attach 宿主
- 页面级覆盖范围
- 编辑器根容器宽高与滚动策略
- 与 `PageFrame` body 的关系
- 缩放稳定性相关样式

不包含：

- 重写为自定义 overlay 组件
- 改造 `PageFrame.vue` 的公共结构
- 修改业务字段、保存逻辑、表格列定义、统计计算逻辑
- 调整左侧菜单、顶栏、全局布局
- 无关 UI 美化

## 3. 现状与问题

当前实现中，`t-dialog` 在桌面端 attach 到 `PageFrame` 的 body 容器，而不是 attach 到 `UnboxRecord` 页面根容器：

- `editorDialogAttach` 在桌面端返回 `unboxRecordBodyRef`
- `showInAttachedElement` 在桌面端开启
- `PageFrame` body 还是一个滚动容器（`overflow-y-auto`）

这带来三个问题：

1. 弹窗的 `width: 100%` / `height: 100%` 实际上是相对于内层滚动 body，而不是整个当前路由页内容区
2. 弹窗与宿主滚动容器叠加，浏览器缩放时更容易出现右侧空白和宽度基准不稳定
3. 编辑器根层还承担了滚动槽预留职责，放大了右侧空白的视觉效果

## 4. 设计原则

1. **覆盖层级正确**：弹窗要覆盖当前路由页内容区，而不是覆盖内层滚动区，也不是覆盖全局视口
2. **滚动职责单一**：页面宿主只负责定位，编辑器内部内容区负责滚动
3. **最小改动**：保留 `t-dialog`、现有按钮、表格、状态与业务逻辑
4. **缩放稳定**：浏览器缩放后不再出现当前这种贯穿式右侧大空白
5. **零业务破坏**：不改变 `draftBatch`、`saveDraftBatch`、表格交互与现有行为语义

## 5. 方案比较

### 方案 A：保留 `t-dialog`，attach 改到页面根宿主（推荐）

做法：

- 给 `UnboxRecord` 页面根容器增加 `pageHostRef`
- `editorDialogAttach` 改为桌面端返回 `pageHostRef`
- `showInAttachedElement` 继续保留
- 页面根宿主负责 `relative` 定位，不承担滚动
- 编辑器自身管理内容滚动

优点：

- 改动最小
- 复用现有 `t-dialog` 结构和交互
- 最贴近“页内覆盖弹窗”的目标
- 可直接切断当前右侧空白的主要成因

缺点：

- 仍受 `t-dialog` DOM 结构约束
- 需要同步梳理滚动层级，否则可能还有细小右侧缝隙

### 方案 B：改成页面级自定义 overlay

做法：

- 不再使用 `t-dialog`
- 在页面根容器中渲染自定义 `absolute inset-0` 覆盖层
- 自己接管头部、关闭、层级、滚动与动画

优点：

- 控制力最强
- 不受 TDesign Dialog 结构限制

缺点：

- 改动更大
- 超出本次问题修复的最小范围

### 方案 C：维持当前 attach，仅修补样式

做法：

- 保持 attach 到 `PageFrame` body
- 仅修改 `overflow`、宽度样式、滚动槽样式

优点：

- 表面改动最少

缺点：

- 根因不变
- 缩放和不同分辨率下仍可能复现

## 6. 最终决策

采用 **方案 A：保留 `t-dialog`，attach 改到页面根宿主**。

原因：

- 完全符合“只覆盖当前路由页内容区”的需求
- 不会扩大为全局覆盖层
- 能以最小改动修正当前层级错误
- 能在不动业务逻辑的前提下解决右侧空白主因

## 7. 具体设计

### 7.1 覆盖层级

`UnboxRecord.vue` 页面根容器作为弹窗宿主。该容器需要：

- 具备 `relative` 定位能力
- 覆盖当前路由页整个内容区
- 不承担额外滚动职责

结果：

- 弹窗打开后覆盖当前页全部内容卡片和列表
- 左侧菜单与顶栏不受影响
- 弹窗 `100%` 宽高以页面根宿主为基准，而不是以 `PageFrame` 内层 body 为基准

### 7.2 attach 策略

桌面端：

- `editorDialogAttach` 返回页面根宿主 `pageHostRef`
- `showInAttachedElement` 保持开启

移动端：

- 继续 attach 到 `body`
- 保持现有移动端全屏行为

这样桌面端与移动端保持既有语义：

- 桌面端是页内覆盖
- 移动端是视口级全屏

### 7.3 滚动层级

本次需要把滚动职责收敛到编辑器内部：

- 页面根宿主：只定位，不滚动
- Dialog 根层：铺满宿主，不承担多余滚动
- 头部区：固定在编辑器顶部布局流中
- 明细内容区 / 表格容器：承担真正滚动

目标：

- 不让宿主滚动和编辑器滚动互相叠加
- 不让页面级 attach 宿主参与右侧滚动槽计算
- 让表格横向滚动只影响表格自身，不影响整个弹窗右侧布局

### 7.4 右侧空白治理

本次治理右侧空白的手段包括：

1. 把 attach 从 `PageFrame` 内层滚动 body 换到页面根宿主
2. 不再让页面宿主承担纵向滚动
3. 移除编辑器根层上的稳定滚动槽预留（如 `scrollbar-gutter: stable`）
4. 保持真正滚动只在内部内容区发生

预期效果：

- 当前截图中那种贯穿整层弹窗的右侧大空白消失
- 缩放后布局稳定
- 即使表格局部有滚动，也只限于表格内容区

### 7.5 兼容性

以下行为保持不变：

- `editorVisible` / `isEditorFullscreen` 的开关语义
- 顶部 `全屏 / 缩小 / 取消 / 保存批次 / 关闭` 按钮行为
- `draftBatch` 数据结构
- `saveDraftBatch` 保存逻辑
- `handleAddRow` / `handleBulkAdd` / `applyDefaultsToEmptyRows` / `mockQueryC5Price`
- 桌面端表格与移动端卡片双形态

## 8. 风险与控制

### 风险 1：页内覆盖范围不够大

如果页面根宿主选错，可能仍然只覆盖局部区域。

控制：

- 宿主必须绑定到 `UnboxRecord` 页面最外层内容容器
- 不绑定到 `PageFrame` body 或更内层表格区域

### 风险 2：宿主仍然保留滚动职责

如果页面宿主仍然是纵向滚动容器，缩放时仍可能出现右侧空带。

控制：

- 宿主只负责定位
- 滚动放入编辑器内部内容区

### 风险 3：全屏 / 缩小模式表现不一致

切换全屏时，如果继续复用错误的宽度类，可能引入新偏差。

控制：

- 保持两种模式共享同一宿主策略
- 只区分是否覆盖页面内容区与是否额外开启遮罩/全屏语义

## 9. 验证标准

改造完成后，满足以下结果即视为达标：

1. 打开“新增批次 / 编辑批次”后，弹窗覆盖 `UnboxRecord` 当前路由页整个内容区
2. 左侧菜单和顶栏不被覆盖
3. 当前截图中的右侧贯穿式大空白消失
4. 浏览器缩放后，弹窗右侧不再出现同等级的大块空白
5. 弹窗内部表格仍能正常滚动、固定列仍正常显示
6. `全屏 / 缩小 / 取消 / 保存批次 / 关闭` 行为不回归
7. 业务数据、保存逻辑、统计逻辑不变

## 10. 实施边界

本次实现只改 `UnboxRecord.vue`，必要时仅做极小样式调整；不扩散到公共布局组件。若后续其它页面也有类似“页内覆盖编辑器”需求，再抽象公共模式。
