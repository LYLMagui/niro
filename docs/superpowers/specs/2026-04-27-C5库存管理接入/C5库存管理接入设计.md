# C5 库存管理接入设计

## 1. 背景

当前项目已完成 C5 扫货账号独立配置，账号表 `c5_sniping_account` 保存账号级 `c5AppKey` 和 Steam 交易链接。C5 官方库存列表接口为：

```text
GET /merchant/inventory/v2/{steamId}/{appId}
```

其中 `app-key` 通过 query 传入，`steamId` 是路径参数，CS2 的 `appId` 为 `730`。当前 `niro-sdk` 已存在 `C5InventoryClient.getInventory(String steamId, String appId, String language, String startAssetId, Integer count)`，但后端业务层未落库，前端 `InventoryManagement.vue` 仍为 mock 数据。

## 2. 目标

本次实现后应满足：

1. 用户能在 C5 扫货账号配置中维护 `steamId`。
2. 用户能在库存管理页按账号刷新 C5 库存。
3. 后端将 C5 库存接口返回的数据保存为最新库存快照。
4. 库存管理页能按账号、名称、状态查询真实库存数据。
5. 已不在最新 C5 返回结果中的历史库存标记为移除，不直接删除。

## 3. 非目标

本次不做以下内容：

- 不保存每次库存刷新历史批次。
- 不实现库存上架接口 `/merchant/sale/v2/create`。
- 不实现上架手续费计算接口 `/merchant/sale/v1/calculate`。
- 不拆分贴纸、宝石、样式等多张子表。
- 不新增自动定时刷新库存任务。
- 不从 Steam 交易链接自动解析 `steamId`。

## 4. 外部接口契约

### 4.1 库存列表

```text
GET /merchant/inventory/v2/{steamId}/{appId}
```

路径参数：

- `steamId`：Steam ID。
- `appId`：游戏 ID，CS2 固定 `730`。

Query 参数：

- `app-key`：C5 AppKey，SDK `C5HttpEngine` 统一注入。
- `language`：语言，默认 `zh`。
- `startAssetId`：分页起点，初始传 `0`，后续传上次返回的 `lastAssetId`。
- `count`：每次查询条数，默认 `1000`。

响应字段：

- `steamId`
- `appId`
- `total`
- `lastAssetId`
- `list[]`
  - `token`
  - `styleToken`
  - `status`：`0` 正常状态，`1` 在售中，`2` 平台禁用不让出售，`3` 永久无法交易，`4` 暂时无法交易且存在冷却时间，`5` 待发货，`6` 除待发货外的其他中间状态，`7` 可出租。
  - `tradableTime`
  - `appId`
  - `assetId`
  - `steamId`
  - `classId`
  - `instanceId`
  - `inspect`
  - `itemId`
  - `name`
  - `shortName`
  - `marketHashName`
  - `imageUrl`
  - `price`
  - `ifTradable`
  - `itemInfo`
  - `assetInfo`

限流：60 秒 1800 次。

## 5. 数据库设计

### 5.1 账号表增量字段

表：`c5_sniping_account`

新增字段：

- `steam_id varchar(64) not null default ''`：库存接口路径参数。

该字段进入账号保存 Param、DTO、Entity 和前端账号配置表单。账号保存时不尝试从 `steamTradeUrl` 解析。

### 5.2 库存快照表

新增表：`c5_inventory_item`

唯一业务键：

```text
account_id + asset_id
```

字段分组：

- `id bigint`

- `account_id bigint`
- `steam_id varchar(64)`
- `app_id integer`
- `asset_id varchar(64)`
- `inventory_status varchar(32)`：`IN_STOCK` / `REMOVED`
- `last_sync_time timestamp`
- `create_time timestamp`
- `update_time timestamp`

#### C5 展示字段

- `token varchar(256)`
- `style_token varchar(256)`
- `c5_status integer`
- `tradable_time varchar(64)`
- `class_id varchar(64)`
- `instance_id varchar(64)`
- `inspect text`
- `item_id varchar(64)`
- `name varchar(255)`
- `short_name varchar(255)`
- `market_hash_name varchar(255)`
- `image_url text`
- `price numeric(12, 2)`
- `if_tradable boolean`

#### CS2 细节字段

- `wear numeric(12, 8)`
- `paint_index integer`
- `paint_seed integer`
- `inspect_image_url text`
- `rarity varchar(64)`
- `rarity_name varchar(128)`
- `rarity_color varchar(32)`
- `exterior varchar(64)`
- `exterior_name varchar(128)`
- `exterior_color varchar(32)`
- `asset_info_json jsonb`
- `item_info_json jsonb`

索引：

- `uk_c5_inventory_item_account_asset`：唯一约束 `(account_id, asset_id)`。
- `idx_c5_inventory_item_user_account_status`：`(user_id, account_id, inventory_status)`。
- `idx_c5_inventory_item_user_name`：`(user_id, market_hash_name)`。
- `idx_c5_inventory_item_sync_time`：`(account_id, last_sync_time desc)`。

约束：

- `inventory_status in ('IN_STOCK', 'REMOVED')`。
- `price >= 0`。
- `app_id > 0`。

### 6.2 刷新接口

```text
POST /api/c5/inventory/refresh
```

入参：

```json
{
  "accountId": 123
}
```

行为：

1. 校验账号属于当前登录用户。
2. 校验账号 `c5AppKey`、`steamId` 不为空。
3. 以 `startAssetId=0`、`count=1000`、`language=zh` 调用 C5 库存接口。
4. 若返回 `lastAssetId` 可继续分页，则循环拉取下一页。
5. 本次拉到的 `assetId` 逐条 upsert 到 `c5_inventory_item`，C5 `status=1` 的库存标记为 `LISTING`，其余返回库存标记为 `IN_STOCK`。
6. 对该账号历史 `IN_STOCK` / `LISTING` 但本次未返回的记录标记为 `REMOVED`。
7. 返回刷新结果：
   - `accountId`
   - `accountName`
   - `total`
   - `addedCount`
   - `updatedCount`
   - `removedCount`
   - `syncTime`

分页终止条件：

- 返回列表为空。
- `lastAssetId` 为空。
- `lastAssetId` 与当前请求 `startAssetId` 相同。

### 6.3 查询接口

```text
GET /api/c5/inventory
```

Query：

- `accountId` 可选。
- `keyword` 可选，匹配 `name` / `marketHashName`。
- `status` 可选：`all` / `tradable` / `cooldown` / `selling`。
- `page`。
- `pageSize`。

查询口径：

- 默认只返回 `inventory_status = IN_STOCK`。
- `tradable`：`inventory_status = IN_STOCK` 且 C5 `status = 0`。
- `cooldown`：`inventory_status = IN_STOCK` 且 C5 `status = 4`。
- `selling`：`inventory_status = LISTING`，来源包括库存刷新返回 C5 `status = 1` 或本地上架提交成功后的状态更新。

### 6.4 账号可选接口

库存页可复用 C5 扫货账号列表接口，也可以新增轻量账号选项接口。优先复用现有账号列表，前端筛出有 `steamId` 的账号用于刷新；没有 `steamId` 的账号仍可展示但刷新时后端拒绝并返回明确错误。

## 7. 前端设计

页面：`niro-client/src/views/InventoryManagement.vue`

改造点：

1. 去除 mock 数据。
2. 新增 API 文件：`src/api/c5-inventory.ts`。
3. 新增类型文件或复用类型：`src/types/c5-inventory.ts`。
4. 账号下拉读取 C5 扫货账号列表。
5. 页面加载时查询库存列表。
6. 点击“刷新库存”：
   - 选择具体账号时刷新该账号。
   - 选择“所有账号”时批量刷新所有配置了 `steamId` 的账号。
7. 刷新成功后重新查询库存。
8. 卡片字段映射：
   - 图片：`imageUrl`
   - 名称：`name` / `marketHashName`
   - 价格：`price`
   - 磨损：`wear`
   - 可交易状态：`ifTradable` / `tradableTime`
   - 账号名称：后端 DTO 补齐 `accountName`

## 8. 错误处理

- 账号不存在或不归属当前用户：后端拒绝。
- 账号缺少 `steamId`：后端拒绝刷新，并提示先在账号配置页补充 Steam ID。
- C5 接口失败：沿用 SDK 异常处理，刷新接口返回失败信息或由全局异常处理。
- 单账号刷新失败不应误标记历史库存为 `REMOVED`。
- 分页异常中断时，本次刷新不执行移除标记，避免误删快照。

## 9. 验证方式

后端：

- 使用指定 JDK 编译 `niro-web`。
- 检查 Flyway migration 语法符合 PostgreSQL。
- 检查账号归属校验、缺少 `steamId`、刷新成功、C5 调用失败等分支。
- 检查刷新后同账号同 `assetId` 不重复插入。
- 检查本次未返回的旧库存被标记为 `REMOVED`。

前端：

- 不启动 dev server，不执行 build。
- 可运行 type-check；页面交互由用户手动验证。
- 手动验证账号筛选、名称搜索、tab 筛选、刷新库存 loading 与空态。

数据库：

- 使用 Flyway 新 migration，不修改历史 migration。
- 不在本地执行 SQL。
- 所有新增表和字段必须补注释。
