# C5 库存管理接入索引

## 主题

接入 C5 库存列表 SDK，按 C5 扫货账号维护库存最新快照，将库存管理前端页面从 mock 数据切换为真实后端接口，并设计库存单个/批量上架、同磨损参考、上架手续费辅助查询，以及 C5 磨损价格快照定时刷新能力。

## 当前状态

库存刷新、查询与上架已落地。当前项目中 `niro-sdk` 已存在 C5 库存列表封装 `C5InventoryClient.getInventory()`，并新增 C5 库存上架封装 `C5InventoryClient.createListing()`；后端已提供库存刷新、库存查询、库存落库、聚合明细查询、统一上架提交、同磨损参考和上架手续费计算链路；前端 `InventoryManagement.vue` 已从 mock 数据切换为真实查询、刷新、明细加载、上架提交、同磨损参考、批量手续费和到手价展示。C5 磨损价格快照已完成设计，待实现。

## 当前有效结论

- 本期只做“最新库存快照”，不保存每次刷新历史批次。
- 库存数据与 C5 扫货账号配置绑定，账号配置需要新增 `steamId` 字段。
- C5 库存刷新使用账号级 `c5AppKey` 和 `steamId`，固定 CS2 `appId=730`。
- 库存快照表使用 `account_id + asset_id` 作为唯一业务键。
- 每次刷新成功后，本次返回的库存按 C5 `status` 映射本地状态：`status=1` 为 `LISTING`，其余返回库存保留为 `IN_STOCK`；该账号历史存在但本次未返回的活跃库存标记为 `REMOVED`。
- 前端库存页账号下拉使用 C5 扫货账号列表，库存卡片使用后端库存查询接口，不再使用 mock 数据。
- 库存上架采用“聚合明细查询 + 统一上架提交”方案：单个上架和批量上架共用 C5 `/merchant/sale/v2/create`，前端只提交本地库存 ID 和价格，后端只允许 C5 `status=0` 的正常库存参与上架，读取 `token` / `styleToken` 后调用 C5；C5 返回成功的资产本地标记为 `LISTING`。
- 库存上架抽屉中的 C5 同磨损参考有磨损区间时通过 C5 `/merchant/market/v2/products/search` 直传区间和页码，无区间时走 `/merchant/market/v2/products/list`；后端仅做当前页兜底过滤，不落库。
- C5 磨损价格快照设计要求库存上架抽屉和开箱记录 C5 在售挂单弹窗不再实时请求 C5，统一读取全局共享快照；快照按 `app_id + market_hash_name + range_type + 归一化 wear_min + 归一化 wear_max` 唯一，后端按固定磨损档位归一化 key；后台采用“XXL-JOB 扫描 + Redis 队列 + 单 worker 消费”，通过 Redis 令牌桶控制 C5 市场查询全局 1 QPS；刷新凭证使用系统级 C5 市场查询 AppKey 池，不默认消耗用户扫货账号 AppKey；前端展示后端返回的刷新状态和上次成功刷新时间。
- 库存上架抽屉中的手续费通过 C5 `/merchant/sale/v1/calculate` 查询，后端保留原始返回并提取展示字段；批量堆叠打开抽屉后使用批量接口一次计算所有明细，单行价格修改后 debounce 重算该行，表格展示手续费和到手价。
- 本期不做库存刷新历史批次、贴纸/宝石/样式子表拆分。
