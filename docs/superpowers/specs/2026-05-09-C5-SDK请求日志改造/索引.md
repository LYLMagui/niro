# C5 SDK 请求日志改造

## 当前状态

已完成。

已落地：

- [x] `niro-sdk` 引入 OkHttp 与 `okhttp-logging-interceptor`。
- [x] `C5HttpExecutor` 内部切换为 OkHttp 同步/异步调用。
- [x] C5 SDK 请求、响应、异常日志改为安全摘要格式。
- [x] `logback-spring.xml` 增加 `com.niro.sdk.c5` 独立 logger/appender。
- [x] Maven 编译验证通过。

## 核心目标

将 C5 SDK 底层 HTTP 客户端从 JDK `HttpClient` 切换为 OkHttp，并建立可区分、可检索、可脱敏的 SDK 请求日志链路。

## 当前有效方案

1. `niro-sdk` 引入 OkHttp 与 `okhttp-logging-interceptor`。
2. 默认生产日志不使用原始 BODY dump，使用自定义 C5 SDK 日志拦截器输出结构化摘要。
3. 保持现有 `C5HttpEngine` 与各 `C5*Client` 对外方法签名不变。
4. `C5HttpExecutor` 内部替换为 OkHttp 同步/异步调用。
5. `logback-spring.xml` 增加 `com.niro.sdk.c5` 独立 logger/appender，将 SDK 日志与业务日志分离。

## 日志口径

### 请求日志

INFO 记录：

- `c5TraceId`
- `method`
- `endpoint`
- 已脱敏、截断后的参数摘要

### 响应日志

INFO 记录：

- `c5TraceId`
- `method`
- `endpoint`
- `status`
- `costMs`
- `success`
- `errorCode`
- `errorMsg`
- `dataSize` 或 `hasData`

### 异常日志

- HTTP 非 2xx：WARN
- C5 业务失败：WARN
- 网络异常、超时、JSON 解析失败：ERROR
- 完整请求体、完整响应体、app-key、token、cookie、密钥类字段不进入 INFO 日志。

## 实现边界

- 不改变 SDK 对外接口和业务调用方。
- 不改 C5 请求参数名和响应 DTO 结构。
- 不引入业务流程到 `niro-sdk`。
- `okhttp-logging-interceptor` 只作为调试能力引入，不默认在生产打印 BODY。

## 推荐阅读顺序

1. 本文件。
2. `变更记录.md`。

## 验证方式

- Maven 编译 `niro-server` 或至少 `niro-sdk` 模块。
- 检查 SDK 同步、异步调用编译兼容。
- 检查日志中 SDK 请求和业务日志可区分。
- 检查敏感字段不会进入 INFO 日志。
