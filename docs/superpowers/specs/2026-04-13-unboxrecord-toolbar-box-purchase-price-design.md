# 开箱记录页：批次明细工具栏箱子购入价设计

## 背景
当前开箱记录页的批次明细工具栏支持快速新增明细（`+1`、`+10`、`+50`、自定义添加）、应用默认值到未填写行，以及拉取市场参考卖价。用户希望在工具栏增加一个可编辑的“箱子购入价”输入项，让新增明细时默认带入该值，并支持一键把该值应用到当前表格所有行。同时，现有“拉取市场参考卖价”按钮和对应功能需要移除。

## 目标
1. 在批次明细工具栏增加“箱子购入价”输入项。
2. 所有新增入口默认使用当前工具栏中的箱子购入价值初始化新行的 `boxPurchasePrice`。
3. 增加“应用箱子购入价到全部”按钮，将当前工具栏值覆盖到当前批次所有明细行。
4. 移除“拉取市场参考卖价”按钮及其 `mockQueryC5Price` 逻辑。
5. 保持现有“应用到未填写行”语义不变，不将箱子购入价逻辑混入其中。

## 范围
仅修改 `niro-client/src/views/UnboxRecord.vue` 中批次明细工具栏与新增明细逻辑，不扩展到后端接口或其他页面。

## 现状
- 批次明细工具栏已有 `+1 / +10 / +50 / 自定义添加`。
- 行级操作区已有“插入”。
- 行数据结构 `UnboxRow` 已存在 `boxPurchasePrice` 字段。
- 新增行逻辑当前通过 `createRow(undefined, draftBatch.value)` 初始化，`boxPurchasePrice` 默认值为 `0`。
- 工具栏存在“拉取市场参考卖价”按钮，调用 `mockQueryC5Price()` 批量更新 `c5Price`。

## 设计

### 1. 工具栏新增箱子购入价输入项
在批次明细工具栏中新增一个紧邻批量新增操作区的输入项：
- 标签：`箱子购入价`
- 组件：`t-input-number`
- 支持两位小数
- 最小值为 `0`
- 默认值初始为 `0`

该值仅作为当前编辑态工具栏参数使用，不放入批次基础信息区，也不引入新的后端字段。

### 2. 新增入口统一使用工具栏箱子购入价
以下入口统一使用当前工具栏值初始化新行的 `boxPurchasePrice`：
- `+1`
- `+10`
- `+50`
- 自定义添加
- 行内“插入”

实现方式：
- 为页面增加一个工具栏级响应式状态，例如 `toolbarBoxPurchasePrice`
- 在 `handleAddRow` 与 `handleBulkAdd` 的行构造路径中显式将其传入 `createRow`
- 行内“插入”继续复用 `handleAddRow(index)`，从而自动获得相同行为

### 3. 新增“应用箱子购入价到全部”按钮
新增按钮：`应用箱子购入价到全部`

行为定义：
- 点击后遍历当前批次 `rows`
- 将每一行的 `boxPurchasePrice` 直接覆盖为当前工具栏值
- 不区分原值是否为空或为 0，统一覆盖
- 操作完成后给出成功反馈；若当前无明细，则按现有页面交互方式给出轻提示

### 4. 保留“应用到未填写行”的原语义
`应用到未填写行` 继续只处理当前已有的默认值补齐逻辑，不额外处理 `boxPurchasePrice`。

原因：
- 该按钮当前语义是“补齐空白默认值”
- 若混入箱子购入价，会让工具栏出现两个语义重叠的批量操作按钮
- 分开后更容易理解：
  - `应用到未填写行`：保留旧逻辑
  - `应用箱子购入价到全部`：处理箱子购入价批量覆盖

### 5. 移除市场参考卖价功能
移除以下内容：
- 工具栏按钮：`拉取市场参考卖价`
- 页面方法：`mockQueryC5Price()`
- 与该按钮直接绑定的前端调用关系

只移除该按钮和方法，不顺手改动现有 `c5Price` 字段、表格列和利润计算逻辑。

## 组件与数据流

### 新增状态
新增页面级工具栏状态：
- `toolbarBoxPurchasePrice: number`

### 更新的数据流
1. 用户在工具栏输入箱子购入价。
2. 用户点击任一新增入口。
3. 新行初始化时读取 `toolbarBoxPurchasePrice`，写入 `row.boxPurchasePrice`。
4. 用户点击“应用箱子购入价到全部”时，当前批次所有行的 `boxPurchasePrice` 被统一更新。

## 错误处理与边界
- 输入框最小值为 `0`，不允许负数。
- 自定义新增数量仍保持现有边界约束（最少 1，最多 200）。
- 若当前表格无明细，批量应用按钮不报错，按现有提示风格返回轻提示。
- 行级“插入”沿用统一新增逻辑，避免出现与工具栏新增行为不一致的分叉。

## 测试与验证
按当前项目协作约束：
- 仅执行前端 `pnpm type-check`
- 不执行前端构建/编译
- 不启动页面做自动抓取验证
- 页面效果由用户手动验证

建议手动验证场景：
1. 修改工具栏箱子购入价后点击 `+1`，新行是否正确带入。
2. 点击 `+10 / +50 / 自定义添加`，批量新增行是否都正确带入。
3. 点击任意行“插入”，插入行是否正确带入。
4. 点击“应用箱子购入价到全部”，现有行是否全部被覆盖。
5. “应用到未填写行”是否仍只处理旧逻辑。
6. “拉取市场参考卖价”按钮是否已消失。
