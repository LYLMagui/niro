# 扫货 2.0 重构索引

## 主题

在保留旧扫货代码但不复用其运行态的前提下，新增一套仅面向 C5 的扫货 2.0 任务域。2.0 采用新的任务表结构、接口、类与方法，重建任务定义、调度、运行状态、命中记录与下单幂等保护；继续复用用户、CS2 商品、订单主数据与底层 C5 SDK，并将 C5 扫货账号从共享 `buff_account` 中拆出为独立 `c5_sniping_account` 主数据。

## 当前状态

核心功能已落地到可运行的 C5 扫货 2.0 首版。当前已存在数据库表、后端 v2 接口、任务 CRUD、单轮占槽调度器、单轮执行器、命中明细、下单尝试明细、SSE 运行态推送和前端页面订阅刷新；已补齐独立 C5 扫货账号表 `c5_sniping_account`、账号归属校验、attempt 级 `out_trade_no`、预占归属字段、可取消停用、在途金额扣减、保守启动恢复、前端 C5 账号选择器、账号运行态表、账号并发上限配置、账号级在途下单数限制、账号短冷却、跨实例调度 lease，以及长期 INIT attempt 的超时核验与终态补偿。扫货配置完整链路已补齐账号运行态配置入口、任务页可用账号接口、账号绑定任务提示和账号配置页批量刷新余额；后续剩余重点是 C5 SDK 侧按 `outTradeNo` 查询远端订单能力、INIT/冷却常量配置化和更完整的调度观测。

## 当前有效结论

- 扫货 2.0 首版仅面向 C5，上线目标是“C5 先上线，后续再考虑多平台抽象”。
- 2.0 以任务域重建为主；商品、订单主数据继续复用，但 C5 扫货账号已从 `buff_account` 中拆出，使用独立 `c5_sniping_account` 主数据；底层 C5 SDK 继续复用。
- 数据库会清空初始化，不存在 1.0 运行态并存问题；旧实现保留源码，不作为 2.0 运行入口。
- 任务模型采用“单商品单任务”。
- 首版运行模型采用单轮占槽扫描，不保留旧版定时、时长、休眠周期模式。
- 停止条件支持两类：按购买数量停止，或按余额停止。
- 余额停止同时支持两种口径：余额低于 `maxPrice`，或低于用户配置的 `reserveBalance`；判断时会扣减同账号未释放 attempt 的在途金额。
- 每个任务固定绑定 1 个账号；一个账号可以绑定多个任务。
- C5 扫货账号不再复用 `buff_account.role` 的扫描号 / 下单号 / 全能号语义，账号配置页和任务绑定链路统一使用独立 `c5_sniping_account`。
- C5 扫货 2.0 不再读取用户全局 C5 AppKey 与 Steam 交易链接；AppKey 和 Steam 交易链接都随 `c5_sniping_account` 账号单独配置。
- 账号并发上限已通过账号运行态配置化，默认值为 5。
- 当前调度模型是一轮扫描短暂进入 `RUNNING`，单轮结束后未完成任务回到 `READY` 并写入 `nextScanAt`，避免同账号多任务长期占槽。
- 同账号同商品允许存在多个任务和多个 READY 任务，但同一时刻最多 1 个任务进入 RUNNING；通过调度过滤、`markRunning` 原子条件和数据库 RUNNING 部分唯一索引共同保证。
- 命中条件只支持价格与磨损，不支持 phase / pattern / sticker，也不为其额外预留业务字段。
- 当前 C5 首版中，`listing_id` 实际对应 C5 `productId`。
- 幂等保护采用双层：本机内存短期去重 + 数据库唯一约束。
- 按购买数量停止的任务采用 `reserved_buy_count` 购买名额预占，attempt 保存 `slot_reserved` / `slot_released` 支撑单次释放与恢复结算。
- 任务定义与运行态拆表：任务表保存长期定义与当前汇总状态，运行实例表记录每次单轮扫描的执行结果。
- 扫描结果只落“命中明细”和“下单尝试明细”，不记录全量扫描快照。
- 异常处理采用连续异常计数；当前实现连续异常达到 3 次后任务进入 ERROR。
- 人工介入只支持任务级启停，不开放实例级运维操作。
- 任务列表展示“任务汇总 + 最近一次运行信息”。
- 扫描频率采用任务级 `scanIntervalMs` 持久化，系统最小间隔为 1 秒；前端任务配置使用秒作为输入单位。
- 任务创建默认为 DRAFT，必须手动启用后才进入调度；任务复制只允许以 `COMPLETED` 任务为来源，前端隐藏非已完成任务的复制入口，后端按 `copySourceTaskId` 强校验来源状态。
- 当前前端页面已落地，任务表单和筛选已使用 C5 账号选择器；页面已通过 SSE 订阅任务运行态事件并按事件轻量刷新列表和明细抽屉。
- 账号配置页只维护账号名称、账号级 C5 AppKey、Steam 交易链接和备注，并展示账号绑定任务提示；支持按当前账号列表批量刷新 C5 账户余额，余额接口使用 `/merchant/account/v2/balance`，`balance` 兼容映射 v2 `moneyAmount`，并展示 `depositAmount`、`tradeSettleAmount`、`creditMoney`、`creditDeposit`；账号级并发上限和最大在途下单数收敛为系统内部运行边界；任务页可用账号接口使用 `/api/c5/sniping/v2/tasks/accounts`。
- C5 AppKey 安全改造采用“数据库 AES-256-GCM 加密存储 + 列表脱敏 + reveal 按需明文 + RSA-OAEP-256 字段级传输加密”方案；历史明文数据通过应用启动迁移写入密文字段，业务不再读取旧明文字段。
- `products/list` 扫描链路会输出业务日志，包含用户 ID、任务 ID、请求 URL、请求入参、C5 返回当前最低价和用户配置最高价；日志不记录 app-key。
- 后续优化重点：C5 SDK 按 `outTradeNo` 查询远端订单、INIT/冷却常量配置化、调度观测与更完整的账号限流配置体验。

1. 先阅读本文件，确认当前有效边界、实现状态与剩余风险。
