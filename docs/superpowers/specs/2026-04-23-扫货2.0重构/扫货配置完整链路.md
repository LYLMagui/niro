# 扫货配置完整链路

## 当前状态

本节记录 C5 扫货 2.0 的配置闭环补齐方案。当前旧 `TaskConfig` / `TaskList` 与旧 `/task/*` 已下线，扫货配置入口统一收敛到 C5 扫货 2.0：

- 任务配置页：`C5SnipingTaskV2`
- 账号配置页：`C5SnipingAccountConfig`
- 任务接口：`/api/c5/sniping/v2/tasks`
- 账号接口：`/api/c5/sniping/v2/accounts`
- 账号主数据表：`c5_sniping_account`
- 账号运行态表：`c5_sniping_account_runtime_v2`

任务配置链路已经覆盖创建、编辑、启停、删除、账号选择、商品选择、价格、磨损、购买目标、停止条件、余额保护和扫描间隔。账号配置链路已经覆盖账号名称、账号级 C5 AppKey、Steam 交易链接、备注和批量刷新余额。

当前账号运行态配置已收敛为系统内部运行边界，前端不再暴露并发上限和最大在途下单数。

## 目标

补齐“账号配置 → 任务配置 → 调度执行”的完整配置闭环，让用户在前端完成 C5 扫货所需的全部关键配置。

本次完成后应满足：

1. 用户可在扫货账号配置页维护账号级 C5 AppKey 与 Steam 交易链接。
2. 用户不需要理解或维护账号级并发上限、最大在途下单数等运行边界。
3. 用户可在 C5 扫货 2.0 任务页选择可用账号并创建任务。
4. 调度器继续按系统内部账号运行态配置控制并发和在途下单数量。
5. 旧 `TaskConfig` / `TaskList` 不再作为扫货配置入口。

## 范围

### 必须补齐

#### 1. 后端账号配置 DTO / Param

`C5SnipingAccountDTO` 增加：

- `concurrencyLimit`：账号级并发上限，默认 1。
- `maxInFlightAttempts`：账号级最大在途下单尝试数，默认 1。
- `boundTaskId`：绑定任务 ID，用于前端删除前提示。
- `boundTaskName`：绑定任务名称，用于前端删除前提示。

`C5SnipingAccountSaveParam` 保留可选内部字段：

- `concurrencyLimit`
- `maxInFlightAttempts`

保存参数约束：

- 用户前端不提交这两个字段。
- 如果内部调用传入，则必须满足 `concurrencyLimit >= 1` 与 `maxInFlightAttempts >= 1`。

#### 2. 后端账号配置服务

`C5SnipingAccountServiceImpl.listAccounts()` 需要合并账号运行态配置：

- 查询 `c5_sniping_account` 基础账号。
- 按账号 ID 查询或兜底创建 `c5_sniping_account_runtime_v2`。
- 将 `concurrencyLimit`、`maxInFlightAttempts` 映射到 DTO。
- 查询未删除任务引用，补齐 `boundTaskId`、`boundTaskName`。

`C5SnipingAccountServiceImpl.saveAccount()` 需要维护运行态配置：

- 创建账号后初始化运行态配置。
- 用户前端更新账号基础信息时不重置既有运行态配置。
- 内部调用传入 `concurrencyLimit`、`maxInFlightAttempts` 时同步更新运行态配置。
- 不允许把并发上限或最大在途下单数保存为小于 1。

`C5SnipingAccountRuntimeV2MapperManager` 增加语义方法：

- 按账号 ID 批量查询运行态配置。
- 保存账号运行态配置。

#### 3. 前端账号配置页

`C5SnipingAccountConfig.vue` 不展示、不编辑账号运行边界字段：

- 不展示并发上限。
- 不展示最大在途。
- 表单不提交 `concurrencyLimit`、`maxInFlightAttempts`。

前端类型 `c5-sniping-account.ts` 保留可选内部字段：

- `concurrencyLimit`
- `maxInFlightAttempts`
- `boundTaskId`
- `boundTaskName`

前端删除按钮使用后端返回的绑定任务字段做提示；后端仍保留最终删除校验。

#### 4. 任务页可用账号接口

`c5-sniping-v2.ts` 中 `getAvailableAccounts()` 改为请求：

```text
GET /api/c5/sniping/v2/tasks/accounts
```

该接口由任务 Controller 提供，语义是“任务配置可选账号”。前端不再用账号配置页的全量账号列表代替。

#### 5. 权限资源

保留：

- `C5SnipingTaskV2`
- `C5SnipingAccountConfig`
- `task:scan:list`

旧资源保持下线：

- `page_task_list`
- `page_task_config`

本次不新增权限码，继续复用 `task:scan:list`。

## 非目标

## 数据流

### 账号配置保存

1. 前端账号配置页提交账号基础信息、AppKey、Steam 交易链接和备注。
2. 后端保存 `c5_sniping_account`。
3. 创建账号时后端初始化 `c5_sniping_account_runtime_v2`。
4. 更新账号基础信息时，后端不重置既有运行态配置。
5. 后端返回账号列表时合并账号基础信息和任务绑定提示，运行边界字段只作为内部能力保留。

### 账号余额刷新

1. 前端账号配置页点击“刷新余额”，提交当前已加载账号的账号 ID 列表。
2. 后端按当前登录用户过滤账号归属，并使用数据库内保存的账号级 `c5AppKey` 调用 C5 `/merchant/account/v2/balance`。
3. 单个账号刷新成功时将 v2 `moneyAmount` 写入 `c5_sniping_account.balance`，将 `tradeSettleAmount` 写入 `pending_balance`，并更新 `deposit_amount`、`credit_money`、`credit_deposit`、`last_check_time` 和 `update_time`。
4. 单个账号刷新失败不影响其他账号，接口返回每个账号的成功状态、余额和说明。

### 任务配置保存

1. 前端任务页调用可用账号接口获取可配置账号。
2. 用户选择账号和 CS2 商品，填写价格、磨损、停止规则、余额保护与扫描间隔。
3. 后端校验账号归属、账号可用性、商品可用性和同账号同商品启用态唯一约束。
4. 任务保存到 `c5_sniping_task_v2`，创建后默认为 `DRAFT`。

### 调度执行

1. 调度器扫描 READY 且到期任务。
2. 按账号读取 `c5_sniping_account_runtime_v2.concurrency_limit`，判断账号是否还有运行槽位。
3. 执行器下单前读取 `max_in_flight_attempts`，限制同账号 INIT 在途下单尝试数。
4. C5 空响应、远端失败或接口异常仍由后端写入短冷却。

## 错误处理

- 账号配置缺少 AppKey 或 Steam 交易链接时，账号状态置为 `INVALID`。
- 用户前端不提交并发上限或最大在途下单数；内部调用提交小于 1 的运行边界时，后端拒绝保存。
- 删除已绑定任务的账号时，后端拒绝删除，前端根据 `boundTaskName` 提前提示。
- 任务创建选择不可用账号时，后端拒绝保存。
- 批量刷新余额时，后端只刷新当前用户拥有的账号；不存在或不归属账号返回失败项，不暴露其他用户账号信息。
- C5 余额接口单账号调用失败时，只标记该账号失败，不中断其他账号刷新。
- 前端只做基础表单校验，最终以服务端校验为准。

## 验证方式

### 后端

- 使用指定 JDK 运行 `niro-web` 编译。
- 检查账号创建接口能写入 `c5_sniping_account` 并初始化 `c5_sniping_account_runtime_v2`。
- 检查账号更新接口不重置既有运行态配置。
- 检查账号列表返回绑定任务提示。
- 检查批量刷新余额接口只按当前用户账号 ID 刷新余额，并能返回单账号成功/失败结果。
- 检查任务创建使用 `/api/c5/sniping/v2/tasks/accounts` 获取可用账号。

### 前端

- 运行 `pnpm type-check`。
- 页面手动验证：账号配置页新增/编辑账号时不出现并发上限和最大在途下单数字段。
- 页面手动验证：账号配置页点击“刷新余额”后按钮进入加载态，完成后提示成功/失败数量并刷新列表余额。
- 页面手动验证：任务页能选择可用账号并创建任务。

### 数据库

- 不修改已执行 migration。
- 如需新增字段或补偿数据，使用新的 Flyway migration。
- 本次预计不新增数据库字段；仅使用已存在的 `c5_sniping_account_runtime_v2`。
