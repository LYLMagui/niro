# C5 任务列表目标配置列增强设计

## 技术规格
Goal: 调整 `niro-client/src/views/TaskList.vue` 中 C5 平台任务列表的“目标配置”展示层级，让最高价与扫描频率同级突出、磨损作为次级信息展示，并在桌面端与移动端同步增加扫描频率信息。
Scope: 仅修改 `niro-client/src/views/TaskList.vue` 的表格列模板、移动端卡片 meta 展示与少量局部样式/格式化逻辑；不改接口、不改 `TaskConfig` 表单、不改 `useTaskForm.ts`、不改后端返回结构。
Risks: 当前表格列宽较紧，目标配置列增强后若排版控制不好，可能导致桌面端单元格拥挤或移动端卡片信息换行过碎。
Compatibility: 保持现有列表字段、分页、筛选、操作行为不变；继续使用已有字段 `maxPrice`、`minPaintwear`、`maxPaintwear`、`scanInterval`、`scanIntervalMin`、`scanIntervalMax`，不引入新接口字段。
Verification: 手动验证桌面端表格与移动端卡片的目标配置展示、不同扫描频率格式、空值兜底、窄屏换行表现，以及新增频率信息后列表整体可读性。

## 背景与现状

当前 C5 任务列表中，“目标配置”列位于 `niro-client/src/views/TaskList.vue:185` 附近，现状为两行浅灰小字：

- `最高价格: ¥xx`
- `磨损: min-max`

存在的问题：

- 视觉权重过低，与创建时间/完成时间列接近，用户扫表时容易忽略
- 没有展示扫描频率，而扫描频率已经是任务表单中的核心配置，见 `niro-client/src/composables/useTaskForm.ts:37-39`
- 移动端卡片只展示最高价格、进度、磨损范围、创建时间，缺少扫描频率，桌面端与移动端信息口径不一致

现有可用字段已经满足展示需求，见 `niro-client/src/types/task.ts:8-19`：

- `maxPrice`
- `minPaintwear`
- `maxPaintwear`
- `scanInterval`
- `scanIntervalMin`
- `scanIntervalMax`

真实问题不是缺字段，而是列表信息层级不对。

## 方案对比

### 方案 A（推荐）：保留单列，改成“双主指标 + 一行补充信息”

做法：

- 保留当前“目标配置”这一列，不拆列
- 列内第一行展示两个同级主指标：`最高价`、`扫描频率`
- 第二行展示次级信息：`磨损`
- 通过轻背景、小圆角、主次文字层级增强可扫读性
- 移动端卡片同步补充扫描频率，并保持同样的信息优先级

优点：

- 改动最小，不破坏当前表格结构
- 同时满足“价格和频率同级突出”的明确要求
- 视觉上比当前醒目，但不会把整张表做得过于花哨
- 与当前页面的朴素表格风格兼容度最高

缺点：

- 信息仍集中在一个单元格内，需要控制好列宽和换行

### 方案 B：拆成“目标配置 + 扫描频率”两列

做法：

- 目标配置列只保留价格和磨损
- 新增独立“扫描频率”列
- 移动端卡片同步拆分信息区域

优点：

- 信息拆分最清晰，不容易漏看

缺点：

- 当前表格列已经较多，再拆列会压缩横向空间
- 会让表格结构更碎，不符合最小改动原则

### 方案 C：主值并排，大值优先

做法：

- 第一行只放两个大值：`¥1.65`、`1-3s`
- 第二行再补标签：`最高价`、`扫描频率`
- 第三行放磨损

优点：

- 扫表速度最快

缺点：

- 对新用户不够直白
- 语义需要用户自行映射，不如方案 A 稳

## 结论

采用 **方案 A**。

理由：这次改造的重点是“让目标配置不再被忽略”，不是重做表格结构。保留单列并重建列内层级，是最小且正确的做法。价格与扫描频率同级突出，磨损降为次级信息，既符合业务优先级，也符合当前页面已有的表格风格。

## 详细设计

### 1. 桌面端目标配置列结构

目标配置列在桌面表格中改为两层结构：

#### 第一层：双主指标

同一行放两个轻量信息块：

- `最高价 ¥1.65`
- `扫描频率 1s` / `扫描频率 1 - 3s`

样式要求：

- 两个信息块同级
- 使用轻背景或浅边框做弱强调，不使用重色块
- 标签字重低于数值，数值为该列视觉焦点
- 两个块之间保持稳定间距，避免粘连

设计目标：

- 用户扫表时先看到价格与频率
- 两者同级，不再由价格单独占据全部注意力

#### 第二层：补充信息

第二行只展示：

- `磨损 0 - 1`

样式要求：

- 使用普通灰字
- 视觉权重低于第一层
- 不再和第一层竞争注意力

### 2. 扫描频率文案与格式规则

对外文案统一使用：

- `扫描频率`

尽管底层字段本质是间隔，列表展示仍按用户更自然的业务口径表达。

格式规则：

- 当 `scanInterval` 有值时，展示：`扫描频率 1s`
- 当 `scanIntervalMin` 和 `scanIntervalMax` 有值时，展示：`扫描频率 1 - 3s`
- 当三者都没有值时，展示：`扫描频率 -`

约束：

- 不改字段含义，不新增后端计算字段
- 仅在前端格式化时完成展示转换

### 3. 数值展示规则

#### 最高价

- 使用 `¥` 前缀
- 若 `maxPrice` 为空，展示 `-`
- 保持与现有页面价格展示口径一致

#### 磨损

- 优先显示 `minPaintwear - maxPaintwear`
- 若一侧为空，使用现有默认认知：最小值默认 `0`，最大值默认 `1`
- 输出示例：`磨损 0 - 1`

#### 扫描频率

- 单值：`1s`
- 区间：`1 - 3s`
- 不在列表页额外引入“秒/每秒/次”混合表述，保持单位统一

### 4. 移动端卡片同步策略

移动端卡片位于 `niro-client/src/views/TaskList.vue:292` 附近，当前 meta 区展示为：

- 最高价格
- 进度
- 磨损范围
- 创建时间

本次调整后同步增加：

- 扫描频率

推荐顺序：

- 最高价格
- 扫描频率
- 进度
- 磨损范围
- 创建时间

这样做的原因：

- 与桌面端的目标配置重点一致
- 不让移动端继续缺少关键信息
- 不新增独立卡片区域，只在现有 meta 网格内补充一项，避免扩大改动

### 5. 视觉风格约束

你已经确认希望风格为 **C2：稍强一点，用轻背景/轻标签强调**。

因此视觉约束如下：

- 不使用大面积高饱和背景
- 不做卡片内再嵌套重卡片
- 只用浅色背景、淡边框或轻标签提升识别度
- 目标配置列的强调程度应高于当前版本，但低于页面主按钮与状态标签

设计边界：

- 不让目标配置列变成页面最抢眼的区域
- 不让整表因单列增强而产生视觉噪音

### 6. 列宽与排版策略

由于目标配置列内新增了扫描频率，需注意排版边界：

- 桌面端保持单元格内容可换行，但优先避免三行以上碎裂
- 主指标块在常规列表宽度下应允许自然换行，不强行单行塞满
- 若空间不足，优先保证主指标完整，磨损信息可以换到下一行

原则：

- 可读性优先于绝对紧凑
- 不为了硬塞同一行而压缩到难以辨认

### 7. 不做的事

本次明确不做：

- 不拆出新列
- 不改接口返回结构
- 不改 `TaskConfig.vue` 表单布局
- 不改 `useTaskForm.ts` 的字段定义和提交逻辑
- 不调整进度列、状态列和操作列结构
- 不引入新的通用组件抽象

原因：

- 当前真实目标只是提升目标配置的可读性，并补充扫描频率
- 继续扩大范围只会增加验证成本

直接影响文件：

依赖但不修改的现有数据来源：

## 验证清单

实现后至少手动检查以下场景：

- 桌面端表格中目标配置列是否明显比当前更易扫读
- `scanInterval` 单值任务是否正确显示 `扫描频率 1s`
- `scanIntervalMin + scanIntervalMax` 区间任务是否正确显示 `扫描频率 1 - 3s`
- 空值场景是否展示 `-`
- 磨损信息是否仍可读但不会压过主指标
- 移动端卡片是否同步展示扫描频率
- 列内容在当前分页尺寸下是否不会产生明显拥挤或错行异常
- 不影响现有分页、筛选、编辑、启动、停止、删除操作

## 成功标准

本次改造完成后，应满足：

- 用户扫表时能一眼看到价格与扫描频率
- 目标配置列不再像注释信息一样被忽略
- 磨损仍保留，但变成辅助判断信息
- 桌面端与移动端对目标配置的展示口径一致
- 不增加额外接口成本，不扩大无关改动范围
