# 订单记录页账号维度改造设计

## 背景
订单记录页当前已经展示“平台/账号”列，但 C5 账号体系已从旧的 `buff_account` 迁移到独立的 `c5_sniping_account`。现有 C5 扫货 2.0 自动下单会把任务绑定账号写入订单记录，而手动同步 C5 订单仍按用户全局 C5 AppKey 拉取，缺少账号选择与订单归属写入。

本次改造目标是把 C5 订单同步、订单筛选和账号回显统一到 C5 独立账号体系，同时保持订单记录表格默认展示当前用户全部账号订单。

## 目标
- 手动同步 C5 订单时必须选择一个 C5 账号。
- 同步接口按所选账号的 C5 AppKey 拉取订单。
- 新同步入库的 C5 订单写入所选 `accountId`。
- 订单记录筛选区增加账号下拉，默认不选中。
- 表格默认返回当前用户全部账号订单；只有筛选账号下拉选中时才按账号过滤。
- 表格“平台/账号”列回显 C5 独立账号名称。

## 非目标
- 不支持一次点击同步全部 C5 账号。
- 不改 C5 平台订单状态映射规则。
- 不改变扫货 2.0 自动下单的下单逻辑。
- 不引入同步进度追踪、批量同步队列或新的历史补偿任务。
- 不调整订单表结构，继续复用现有 `trade_order_record.account_id`。

## 方案结论
采用“同步单账号 + 列表可选账号筛选”的方案。

原因：
- 同步时的 C5 AppKey、订单归属和前端选择是一一对应关系，语义清晰。
- 和 C5 扫货 2.0 的独立账号体系一致。
- 避免“全部账号同步”带来的耗时、锁粒度、重复订单归属和错误隔离复杂度。
- 保持订单列表默认视图不变：用户进入页面仍看到全部账号订单。

## 前端改动设计
### 同步区域
在订单记录页现有“同步范围”旁增加“同步账号”下拉框。

交互规则：
1. 页面加载时拉取当前用户 C5 账号列表。
2. 用户选择同步账号和同步范围。
3. 点击“同步 C5 订单”时传递 `accountId` 与 `daysBefore`。
4. 未选择同步账号时，不触发接口，并提示用户先选择 C5 账号。
5. 同步中禁用同步账号下拉、同步范围下拉和同步按钮。

同步账号选项：
- 数据来源复用 C5 扫货账号接口。
- 展示文案优先使用账号名称，可附带账号 ID 便于区分重名账号。
- 仅用于触发同步，不影响表格默认查询条件。

### 筛选区域
在订单记录页筛选框增加“账号”下拉框。

筛选规则：
- 默认值为空，表示不过滤账号。
- 为空时，请求不传 `accountId`，后端返回当前用户全部账号订单。
- 选中账号时，请求传 `accountId`，后端只返回该账号订单。
- 重置筛选时清空 `accountId`，恢复全部账号订单。

### 表格回显
现有“平台/账号”列继续保留。

回显规则：
- `platform = C5` 且 `accountId > 0` 时，展示 C5 独立账号名称。
- `platform = BUFF` 且 `accountId > 0` 时，继续展示 Buff 账号名称。
- 找不到账号或 `accountId` 为空时展示 `-`。

## 后端改动设计
### 同步接口
手动同步接口新增 `accountId` 参数。

接口语义：
- `accountId` 必填。
- 后端必须校验该账号属于当前登录用户。
- 后端使用该账号的 `c5AppKey` 构造 C5 客户端。
- 同步任务消息携带 `accountId`。
- 分布式锁和提交冷却应纳入 `accountId`，避免不同账号之间互相阻塞。

推荐方法签名演进：
- `submitSyncTask(Long userId, Long accountId, Integer daysBefore)`
- `syncOrders(Long userId, Long accountId, Integer daysBefore)`
- 内部同步方法接收账号实体或 `accountId + appKey`。

### 订单入库
同步 C5 订单转换为 `TradeOrderRecord` 时写入：
- `userId`
- `accountId`
- `platform = C5`
- `orderId`
- `outTradeNo`
- `price`
- `status`
- 商品信息
- 创建与更新时间

重复判断仍按现有平台订单号逻辑执行，不因为本次改造改成按账号重复判断。

### 订单分页查询
订单分页接口增加可选 `accountId` 参数。

查询规则：
- 必须始终限定当前登录用户 `userId`。
- `accountId` 为空时不增加账号条件，返回当前用户全部账号订单。
- `accountId` 非空时增加 `TradeOrderRecord.accountId = accountId` 条件。
- 为避免越权，后端应校验该账号属于当前用户，或在查询条件中同时限制当前用户订单。

### 账号名称回显
订单 DTO 组装时按平台选择账号来源：
- C5 订单：从 `c5_sniping_account` 查询账号名称。
- BUFF 订单：从 `buff_account` 查询账号名称。

为了避免分页列表产生过多单条查询，优先按本页订单中的账号 ID 批量查询账号名称映射，再回填到 DTO。

## 数据流
### 同步 C5 订单
1. 前端选择同步账号和同步范围。
2. 前端调用同步接口，传 `accountId` 与 `daysBefore`。
3. 后端校验登录用户和账号归属。
4. 后端提交同步 MQ 消息，消息携带 `userId/accountId/daysBefore`。
5. 消费端按账号 AppKey 拉取 C5 订单。
6. 新增订单保存到 `trade_order_record`，写入 `accountId`。
7. 前端提示任务已提交或同步完成，并刷新订单列表。

### 查询订单记录
1. 页面初始化时不传 `accountId`。
2. 后端返回当前用户全部账号订单。
3. 用户选择筛选账号后，请求携带 `accountId`。
4. 后端按 `userId + accountId` 返回订单。
5. DTO 回填平台对应账号名称。

## 兼容性
- 扫货 2.0 自动下单已有 `accountId` 写入逻辑，保持不变。
- 历史手动同步 C5 订单可能没有 `accountId`，列表仍展示在“全部账号”默认视图中。
- 选择某个账号筛选时，历史无账号订单不会被返回。
- 前端默认表格查询不传 `accountId`，避免上线后默认列表突然变窄。
- 同步接口新增必填账号后，旧前端调用会被拒绝；本次改造必须前后端同步发布。

## 验收标准
- 订单记录页同步区域可选择 C5 账号。
- 未选择同步账号时点击同步会提示用户选择账号，不发送同步请求。
- 选择账号后触发同步，请求携带 `accountId` 与 `daysBefore`。
- 后端使用所选 C5 账号的 AppKey 同步订单。
- 新同步入库的 C5 订单写入 `accountId`。
- 订单记录筛选区可按账号筛选。
- 页面初始加载与重置筛选后返回当前用户全部账号订单。
- C5 订单“平台/账号”列回显 C5 独立账号名称。
- BUFF 订单账号回显不受影响。
