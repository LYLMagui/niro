# 订单记录页同步范围选择设计

## 背景
当前订单记录页的“同步 C5 订单”按钮会直接以固定参数触发同步，前端实际传入的是 `daysBefore = 1`，等价于默认同步“昨天 00:00:00 到现在”的数据。这个行为在界面上不可见，用户无法在操作前明确知道同步范围，也无法根据需要切换同步天数。

本次设计目标不是改后端协议，而是在保持现有默认行为兼容的前提下，让用户可以在前端显式选择同步范围。

## 目标
- 让用户在订单记录页直接选择同步范围
- 保持默认行为与当前实现一致
- 继续复用现有后端 `daysBefore` 参数，不新增接口协议
- 不引入额外弹窗或多余确认流程，保持高频操作顺畅

## 非目标
- 不改后端同步逻辑
- 不新增自定义天数输入
- 不改成日期范围选择器
- 不引入“确认同步”弹窗

## 用户交互设计
### 交互结构
在订单记录页顶部操作区，保留现有“同步 C5 订单”按钮，并在按钮旁边新增一个“同步范围”下拉框。

用户流程：
1. 查看当前下拉选中的同步范围
2. 如有需要，切换同步范围
3. 点击“同步 C5 订单”按钮
4. 按当前选中范围触发同步

### 选项定义
固定提供以下 5 个选项：
- 今天 → `0`
- 昨天 → `1`
- 最近 3 天 → `3`
- 最近 7 天 → `7`
- 全部 → `-1`

### 默认值
默认选中“昨天”。

原因：
- 与当前线上行为保持一致
- 老用户操作习惯不变
- 避免 UI 改造后意外扩大默认同步范围

## 文案设计
- 主按钮文案：`同步 C5 订单`
- 下拉标签文案：`同步范围`
- 下拉选项文案：今天 / 昨天 / 最近 3 天 / 最近 7 天 / 全部

## 状态反馈设计
### 加载态
点击同步按钮后：
- 按钮进入 loading 状态
- 下拉框同步禁用
- 同步结束后恢复可操作状态

### 成功提示
成功提示应带上当前范围文案，避免只提示“完成”却看不出本次范围。

建议文案：
- 今天：`C5 订单同步完成（今天）`
- 昨天：`C5 订单同步完成（昨天）`
- 最近 3 天：`C5 订单同步完成（最近 3 天）`
- 最近 7 天：`C5 订单同步完成（最近 7 天）`
- 全部：`C5 订单同步任务已提交（全部历史）`

其中“全部”单独使用“任务已提交”语义，是为了给用户明确的耗时预期，避免误以为这是一个很快完成的操作。

### 结果刷新
同步成功后，如果当前用户有订单记录查看权限，沿用现有行为刷新订单列表。

## 风险提示设计
仅当用户选中“全部”时，在下拉框附近展示弱提示：

`全部历史同步耗时可能较长`

该提示只用于建立预期，不额外引入确认弹窗，不增加新的交互分支。

## 前端数据结构设计
前端应维护一份统一的同步范围选项配置，至少包含：
- 选项值（用于传给接口）
- 选项文案（用于下拉展示）
- 成功提示文案或可派生的展示文案
- 是否为高耗时选项（用于“全部”弱提示）

这样可以保证：
- 下拉展示
- 接口传参
- 成功提示
- 风险提示

都从同一份配置派生，避免在页面里散落多份魔法数字和重复判断。

## 接口兼容性设计
本次改造不改后端接口协议，继续调用现有同步接口并传递 `daysBefore`。

兼容要求：
1. 未修改下拉值时，点击按钮的默认行为与当前完全一致
2. 后端仍按原有 `daysBefore` 逻辑处理
3. 页面只增加前端选择能力，不改变同步任务本身的业务语义

## 方案对比结论
本次最终采用：**主按钮 + 旁边下拉选择范围**。

未采用其他方案的原因：
- 弹窗选择会打断高频操作
- Split Button 或隐藏入口虽然更紧凑，但会把真实存在的重要参数藏起来，增加理解成本
- 当前任务的重点是把“同步多少天”显式化，而不是做复杂交互

## 实现范围
本次实现仅覆盖订单记录页同步入口相关前端交互：
- 操作区 UI 调整
- 同步范围状态管理
- 接口调用参数改为使用用户所选值
- 同步成功提示优化
- “全部”弱提示展示

不包含：
- 后端接口改造
- 任务中心同步入口联动
- 历史同步进度追踪
- 自定义日期/自定义天数能力

## 验收标准
- 订单记录页可见“同步范围”下拉框
- 默认值为“昨天”
- 用户可在 5 个固定范围中切换
- 点击“同步 C5 订单”时，实际传入当前选择的 `daysBefore`
- 同步中按钮 loading、下拉禁用
- 成功提示能体现本次同步范围
- 选中“全部”时可见弱提示
- 不改默认兼容行为
