# 开箱记录页：净利润与利润率排序设计

## 背景
当前开箱记录页包含两层表格：
1. 批次汇总表
2. 批次明细编辑表

用户希望为“净利润”和“利润率”两类列增加排序功能，并要求：
- 批次汇总表和批次明细表都支持
- 点击列头的行为为：升序 → 降序 → 恢复默认顺序
- 对于界面展示为 `—` 的项，排序时按 `0` 处理
- 净利润列只根据利润数值排序，不按展示文案、颜色或其他样式因素排序

## 目标
1. 为批次汇总表增加净利润/利润率排序能力。
2. 为批次明细表增加净利润/利润率排序能力。
3. 排序仅影响当前视图顺序，不永久修改底层数据数组顺序。
4. 保持当前文案、颜色、固定列和表尾逻辑不变。

## 范围
仅修改 `niro-client/src/views/UnboxRecord.vue` 中两张表的列定义与视图层排序逻辑，不涉及后端接口、持久化字段或利润计算公式。

## 现状
- 批次汇总表当前展示总预估净利润、总实际净利润等汇总指标，但无排序能力。
- 批次明细表当前展示净利润、利润率等列，但无排序能力。
- 利润类展示存在 `—` 文案，用于表示无可用值。
- 当前页面中的行顺序和批次顺序均直接来自底层数组，适合保留为“默认顺序”。

## 设计

### 1. 排序能力覆盖范围
#### 批次汇总表
增加排序的列：
- `总实际净利润`
- `总利润率`（若现有列标题以实际文案呈现，则按当前列文案为准）

排序值：
- 总实际净利润：`summary.totalActualNetProfit`
- 总利润率：`summary.totalActualProfitRate ?? 0`

#### 批次明细表
增加排序的列：
- `净利润`
- `利润率`

排序值：
- 净利润：`entry.metrics.actualNetProfit ?? 0`
- 利润率：`entry.metrics.actualProfitRate ?? 0`

其中净利润列严格只按利润数值本身排序，不受当前展示格式、颜色、正负号样式或 `—` 文案影响。

### 2. 点击交互规则
两张表统一采用以下排序交互：
1. 第一次点击列头：升序
2. 第二次点击列头：降序
3. 第三次点击列头：恢复默认顺序

这样可以保证用户在查看排序结果后，能快速回到页面原本的编辑顺序或批次顺序。

### 3. `—` 的排序语义
界面上显示为 `—` 的项目，在排序时统一按 `0` 参与排序。

这意味着：
- 展示文案保持不变，仍显示 `—`
- 排序时把它视作数值 0

这样既满足用户要求，也避免为了排序去改动现有展示逻辑。

### 4. 默认顺序定义
#### 批次汇总表默认顺序
恢复默认顺序时，回到 `batches.value` 当前生成的原始顺序。

#### 批次明细表默认顺序
恢复默认顺序时，回到 `draftBatch.value.rows` 当前生成的原始顺序。

实现上，排序不应直接重写底层数组顺序，而应通过视图层排序能力完成，这样不会影响：
- 插入行位置
- 新增明细顺序
- 删除后的原始编辑流

### 5. 实现策略
采用 TDesign 表格原生排序能力：
- 在目标列上启用排序能力
- 为每列提供明确的排序值或排序函数
- 排序函数只依赖数值，不依赖格式化后的字符串

不额外手写全局排序状态管理，避免为两个列的简单排序引入一整套自定义排序系统。

## 数据与职责边界
- 利润数值来源仍由现有 `summary` 和 `metrics` 计算逻辑负责
- 表格列只负责声明“按哪个值排序”
- 展示函数继续负责格式化货币、百分比和 `—`
- 排序不介入利润计算本身

这样可以保持职责分离：
- 计算层：算数值
- 展示层：格式化显示
- 表格层：基于数值排序

## 错误处理与边界
- 若某列值不存在，按 `0` 排序
- 排序恢复默认时，不报错，不改变底层数组
- 固定列、表尾、按钮操作、编辑输入框不因排序行为改语义

## 测试与验证
按当前项目协作约束：
- 仅执行前端 `pnpm type-check`
- 不执行前端构建/编译
- 不启动页面做自动抓取验证
- 页面效果由用户手动验证

建议手动验证场景：
1. 批次汇总表点击净利润列头，验证升序/降序/恢复默认顺序。
2. 批次汇总表点击利润率列头，验证升序/降序/恢复默认顺序。
3. 批次明细表点击净利润列头，验证升序/降序/恢复默认顺序。
4. 批次明细表点击利润率列头，验证升序/降序/恢复默认顺序。
5. 含 `—` 的行或批次是否按 `0` 排序。
6. 排序后插入、新增、删除操作的原始编辑顺序在取消排序后是否恢复正常。

## 范围控制
本次不做以下事情：
- 不新增多列联合排序
- 不新增默认排序规则
- 不修改利润公式
- 不修改 `—` 的展示文案
- 不把排序结果持久化到本地或后端
