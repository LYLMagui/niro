# UnboxRecord 新增批次编辑器工作台化改造设计

日期：2026-04-06  
文件：`niro-client/src/views/UnboxRecord.vue`

## 1. 目标

将“新增批次 / 编辑批次”弹窗从“多张信息卡堆叠”改成更接近录单工作台的结构。

核心目标：

- 保留当前页面的轻量产品风格，不改成传统 ERP 视觉
- 借鉴参考页的录单顺序：头信息 → 明细工具条 → 明细表格
- 顶部继续作为唯一主操作区
- 降低统计信息优先级，让明细录入成为页面主任务
- 保持现有字段、业务逻辑、数据结构和保存行为不变

## 2. 范围

本次只调整 `UnboxRecord.vue` 中批次编辑器弹窗的布局与交互组织：

- 顶部标题栏
- 头表单区
- 明细区工具条
- 统计展示形式
- 表格结果列的视觉层级
- 全屏 / 缩小态下的工作台组织方式

不包含：

- 新增业务字段
- 修改保存逻辑
- 修改数据计算逻辑
- 新增底部固定操作栏
- 新增“保存并继续编辑”等新动作

## 3. 设计原则

1. **录入优先**：打开弹窗后的首要任务是填批次头和录明细，不是看统计。
2. **结构学 ERP，视觉保持现状**：学习参考页的信息组织方式，但继续沿用当前轻量白底、圆角、留白体系。
3. **操作集中**：顶部保持唯一主操作区，避免顶部/底部双操作栏并存。
4. **表格是主角**：批量动作、辅助动作、summary 都为表格服务，不再和表格争夺版面。
5. **零破坏兼容**：不改变现有字段含义、交互语义和保存入口。

## 4. 页面结构

### 4.1 顶部标题栏

顶部继续保留为唯一操作栏，结构如下：

- 左侧：
  - 标题（新增开箱批次 / 编辑开箱批次）
  - 批次类型标签（新增批次 / 编辑批次）
  - 当前明细数标签
- 右侧：
  - 全屏 / 缩小
  - 取消
  - 保存批次
  - 关闭按钮

### 4.2 头表单区

头表单区改成“单据头”思路，仍保留当前白底和圆角，但视觉弱化为录入容器，而不是强卡片。

字段分两层：

- 第一层主字段：
  - 批次名称
  - 开箱日期
  - 箱子类型
- 第二层补充字段：
  - 默认箱子成本
  - 默认折扣
  - 备注

约束：

- 不改字段顺序语义
- 不再在这个区块内突出“当前明细 N 条”这类统计型信息
- 标题“批次信息”可以保留，但弱化为辅助区块标题

### 4.3 明细主区

明细区改成三层：

#### 区块头

- 左侧：`批次明细`
- 右侧：桌面端表格 / 移动端卡片提示

#### 工具条

工具条分左右两组：

- 左组：录入动作
  - 新增一行
  - +10
  - +50
  - 自定义新增
- 右组：辅助动作 + 轻量 summary
  - 应用默认值
  - 查询 C5 价格
  - summary strip（例如总条数、已购买数、预估利润、实际利润）

#### 表格主体

- 桌面端继续使用表格
- 移动端继续使用卡片结构
- 保持现有字段和录入逻辑

## 5. 统计信息降级策略

现有独立统计卡 section 不再保留为完整块级区域。

改造后：

- 统计内容收编到明细区工具条附近
- 以轻量 summary strip 展示
- 展示目标是“辅助判断”，不是“抢占录入前视线”

推荐保留的 summary 信息：

- 总条数 / 已购买数
- 总箱子成本 / 实际花费
- 总预估利润
- 总实际利润

但视觉上改成单行或双行轻量摘要，不再使用高存在感卡片布局。

## 6. 表格视觉策略

桌面端表格继续沿用当前压缩后的列结构，并保持：

- `预估结果` 代替 `预估利润 + 预估利润率`
- `实际结果` 代替 `实际利润 + 实际利润率`

进一步调整方向：

- 结果列保留双行信息组织
- 视觉从“嵌套小卡片”进一步收成“轻量结果块”
- 录入列优先级高于结果列
- 表头和说明文案继续减噪

目标是让表格更像录入工作表，而不是展示面板。

## 7. 顶部操作栏交互优先级

顶部操作仍然只保留一组，不新增底部固定栏。

优先级定义：

1. `全屏 / 缩小`：布局模式切换动作
2. `取消`：次级动作
3. `保存批次`：唯一主动作
4. `关闭`：最轻量退出动作

约束：

- 顶部仍然是唯一主操作入口
- 不新增双保存区
- 不新增保存分支动作

## 8. 全屏 / 缩小态行为

### 全屏态

- 覆盖顶部导航栏以下的页面工作区
- 更强调“工作台”组织
- 明细区吃满主要可用空间

### 缩小态

- 限制在当前页面容器内
- 保留相同的信息组织顺序
- 只是缩小工作区，不改变布局逻辑

两种模式共享同一套内容结构，不做两套不同页面。

## 9. 响应式策略

### 桌面端

- 优先呈现完整工作台结构
- 头表单横向排布
- 明细主区突出表格

### 移动端

- 保持全屏
- 头表单改为纵向堆叠
- 工具条允许上下换行
- 明细继续使用卡片，不强行压成表格

## 10. 兼容性要求

以下内容必须保持不变：

- `draftBatch` 数据结构
- `draftSummary` / `draftSummaryCards` 的计算来源
- `saveDraftBatch` 行为
- `handleAddRow` / `handleBulkAdd` / `applyDefaultsToEmptyRows` / `mockQueryC5Price` 行为
- 现有购买状态切换语义
- 移动端和桌面端双形态入口

允许修改的是展示层级、区块组织、按钮摆放顺序和样式强弱。

## 11. 验证标准

改造完成后，满足以下结果即视为达标：

1. 打开弹窗后，用户能先看到清晰的头表单，再自然进入明细区
2. 统计信息不再作为独立主区块抢占视线
3. 顶部操作栏仍然是唯一主操作区，且层级清楚
4. 明细工具条与表格关系更紧密
5. 全屏态更像完整录入工作台，缩小态只是容器缩放，不是另一套布局
6. 不破坏现有字段、计算、保存逻辑和移动端卡片结构

## 12. 最终决策

采用 **折中工作台方案（B）**：

- 结构借鉴 ERP 录单页
- 视觉保持当前轻量风格
- 操作栏保留顶部
- 统计降级为明细区轻量摘要
- 表格继续作为页面主角
