# 按钮权限与超级管理员锁定

## 目标
本文件补充全量按钮权限迁移与超级管理员角色锁定规则。目标是让后台业务按钮全部进入新权限系统，同时保证超级管理员角色始终拥有全部资源权限，且不能在权限管理页被勾选或取消勾选。

## 当前结论
- 超级管理员角色统一按 `sys_role.role_key = 'admin'` 识别；现有 `userId = 1` 管理兜底本期保留，不作为权限页锁定口径。
- `role_key = 'admin'` 的角色在权限管理页中始终显示为全选且禁用。
- 前端禁用只用于交互防误操作；后端保存角色授权时必须拒绝修改 admin 角色授权。
- 发布时自动补齐 admin 角色对全部发布态资源的授权，避免草稿或发布态数据漂移导致超管缺权。
- 状态型业务禁用不被超级管理员权限覆盖，例如运行中任务不可编辑或删除、已绑定任务账号不可删除。

## 按钮纳管范围
纳管范围只包含后台业务页面内会改变数据、触发外部动作或进入敏感配置的操作按钮。查询、重置、详情等查看类操作可复用页面查看权限，不强制拆成独立按钮权限。

需要纳管的页面与动作：
- `Dashboard`：启动任务、停止任务。
- `GoodsList`：同步分类商品、扫货入口；扫货入口的业务禁用状态继续保留。
- `OrderRecord`：行删除、批量删除、同步 C5 订单。
- `Settings`：BUFF 账号新增/编辑/保存、一键检测、单账号检测、删除、保存全局配置、发送测试消息。
- `InviteCodeManageNew`：新建、批量生成、批量停用、编辑、启用、停用、复制。
- `PermissionManageNew`：资源保存、角色创建/编辑/删除/复制、用户分配角色、角色预览、发布校验、执行发布。
- `C5SnipingTaskV2`：新增、编辑、保存、开启、停止、删除、详情类记录入口。
- `C5SnipingAccountConfig`：新增、编辑、提交、详情、删除；已绑定任务账号的删除入口必须业务禁用。
- `UnboxRecord`：新建/编辑/保存批次、删除批次、OCR、C5 查询、增删明细、应用价格或默认值。

不纳入业务按钮权限的范围：
- `403`、`404`、`login` 页面按钮。
- `Layout` 刷新、退出、关闭页签等通用框架按钮。
- `CronEditor` 等通用组件内部按钮；由调用页面决定是否展示或禁用。

## 权限码规则
- 沿用已有稳定权限码时不强行重命名，例如 `buff:account:save`、`buff:account:delete`、`system:invite-code:manage` 可在迁移中逐步拆细。
- 新增按钮权限码按 `领域:资源:动作` 命名，例如 `c5:sniping-task:create`、`unbox:record:ocr`、`system:permission:publish`。
- 删除、启停、同步、发布、外部查询、OCR、角色分配等动作优先使用独立权限码。
- 页面查看权限和按钮操作权限分离；按钮资源必须能沿父级链路归属到有效 `PAGE`。

## 前端实现规则
- 页面按钮统一消费新按钮权限接口返回的权限码，优先使用现有新权限 store、`useNewPermission` 或等价封装。
- 旧 `usePermission`、旧 `permission` 指令和旧用户权限码不再作为新页面按钮权限真源。
- 超级管理员角色在 `PermissionManageNew` 的授权树中显示全选且禁用；保存按钮禁用或提示不可修改。
- 业务状态禁用必须继续保留，不允许因为超级管理员拥有权限而放开不可执行状态。

## 后端实现规则
- 角色授权保存接口识别目标角色 `role_key = 'admin'` 时直接拒绝修改。
- 发布流程在写入 `role_resource_published` 时自动补齐 admin 角色对全部 `resource_published` 的授权。
- 草稿态也要保持 admin 角色全量授权，使权限页读取草稿时和发布态一致。
- 不新增发布批次、回滚或审批流，不改变现有双表草稿/发布模型。

## 数据迁移规则
- 通过新增 Flyway 补偿 migration 写入缺失的 `BUTTON` 资源，不修改历史 migration。
- 同步写入 `resource_draft` 与 `resource_published`。
- 使用 `resource_key`、`permission_code` 与 `role_key = 'admin'` 定位，不依赖自增 id。
- 给 admin 角色补齐全部资源授权到 `role_resource_draft` 与 `role_resource_published`。
- migration 必须幂等，重复执行不得产生重复资源或重复授权。

## 验收标准
- 后台业务页面的修改类、危险类和敏感类按钮均有新按钮权限资源。
- 普通角色只看到或可操作已授权按钮。
- `role_key = 'admin'` 的角色在权限管理页始终全选且不可勾选或取消勾选。
- 后端拒绝保存 admin 角色授权修改。
- 发布后 admin 角色在草稿态和发布态都拥有全部资源授权。
- 状态型禁用对超级管理员仍然生效。
