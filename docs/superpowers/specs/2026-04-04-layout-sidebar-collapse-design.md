# Layout 侧栏收缩设计

## 技术规格
Goal: 为 `niro-client/src/components/Layout.vue` 的左侧菜单增加可收缩能力，展开时显示图标+文字，收起时保留图标窄侧栏，并在收起状态下通过弹层承载子菜单。
Scope: 仅涉及 `niro-client/src/components/Layout.vue` 的布局状态、菜单交互与局部样式；必要时少量补充全局样式，但不修改路由结构、菜单数据结构、tabs 逻辑与业务页面。
Risks: 当前菜单样式对 TDesign 做了较多 `:deep()` 覆盖，折叠态下可能出现图标不居中、激活态偏移、弹层被裁切或 hover 区域异常。
Compatibility: 不改 `transformRoutesToMenus()` 输出，不改 `tabsStore`、路由跳转与现有页面内容，只新增一个默认展开的本地 UI 状态；刷新后恢复展开。
Verification: 手动验证展开/收起切换、一级菜单跳转、收起态子菜单弹层、当前路由高亮、内容区宽度变化、刷新后默认展开。

## 背景与现状

当前布局是标准的 `header + aside + content` 三段式结构：

- 顶部栏位于 `niro-client/src/components/Layout.vue:3`
- 左侧菜单栏位于 `niro-client/src/components/Layout.vue:49`
- 菜单本体位于 `niro-client/src/components/Layout.vue:54`
- 内容区位于 `niro-client/src/components/Layout.vue:105`

现状特点：

- 左侧栏宽度固定为 `150px`
- 菜单始终展示图标、文字和子菜单结构
- 顶部栏没有侧栏折叠入口
- 路由高亮依赖 `activeValue`
- 菜单样式在 `Layout.vue:216` 之后存在较多局部深度覆盖

真实问题不是菜单数据结构不对，而是左栏长期占用内容区宽度，尤其在列表页、表格页里更明显。

## 方案对比

### 方案 A（推荐）：双态侧栏 + 收起态弹层子菜单

做法：

- 在 `Layout.vue` 中新增本地状态 `collapsed`
- 展开态保持当前菜单形态不变
- 收起态将侧栏压缩为仅图标窄栏
- 顶部左侧新增折叠按钮
- 收起后点击有子项的一级菜单，通过弹层展示二级菜单

优点：

- 与当前后台布局最匹配
- 不触碰菜单数据结构和路由逻辑
- 改动聚焦在布局层，风险集中、可控
- 交互符合大多数管理后台习惯

缺点：

- 需要额外处理收起态 submenu 展示
- 需要校准当前自定义样式与折叠态之间的冲突

### 方案 B：依赖 TDesign 原生折叠菜单能力

做法：

- 让 `t-menu` 与 `t-aside` 跟随折叠状态切换
- 尽量复用组件库默认的 icon-only 和 submenu 行为

优点：

- 组件行为更统一
- 理论上更少手写逻辑

缺点：

- 当前 `Layout.vue` 菜单样式覆盖较深，和原生折叠模式容易冲突
- 最终通常仍需要较多样式修补
- 真实改动量未必比方案 A 更小

### 方案 C：纯视觉压缩，不真正区分展开/收起菜单模式

做法：

- 仅缩窄侧栏并隐藏文字
- 子菜单通过额外规则临时显示或改成其他入口

优点：

- 表面实现最快

缺点：

- 交互容易不一致
- 后续容易堆补丁
- 不是干净的数据与交互边界

## 结论

采用 **方案 A**。

理由：当前问题是布局宽度利用率，而不是菜单模型本身。最小且正确的改法，就是给现有侧栏增加双态显示能力，保持展开态原样，收起态只改变展示方式，不把 UI 问题扩散到路由、store 或菜单转换逻辑。

## 详细设计

### 1. 布局状态设计

在 `niro-client/src/components/Layout.vue` 中新增本地状态：

- `collapsed: Ref<boolean>`

规则：

- 默认值为 `false`
- 点击顶部蓝色栏左侧按钮时切换
- 不写入 localStorage、Pinia 或其他持久化介质
- 页面刷新后恢复默认展开

布局行为：

- 展开态：侧栏保持当前宽度和结构
- 收起态：侧栏缩窄为 `56px`
- 主内容区继续依赖现有 flex 布局自动扩展，不额外引入复杂计算

### 2. 顶部折叠入口设计

在顶部蓝色栏左侧增加一个折叠按钮，位置靠近标题区域。

规则：

- 与 `Niro Control` 处于同一行
- 使用明确的展开/收起图标语义
- 点击后立即切换 `collapsed`
- 不影响现有刷新按钮、用户菜单和退出逻辑

设计目标：

- 折叠入口始终可见
- 操作路径短，不要求用户把鼠标移到侧栏边缘寻找开关

### 3. 侧栏展示设计

#### 展开态

保持现有行为：

- 宽度保持当前展开态比例
- 菜单项显示图标、文字、箭头
- 子菜单继续按当前方式展开
- `activeValue` 高亮逻辑保持不变

#### 收起态

侧栏压缩为窄栏，仅保留一级菜单图标。

具体规则：

- 隐藏菜单文字
- 隐藏常驻箭头
- 二级缩进内容不在窄栏内部展开
- 每个一级菜单项保持完整 hover 热区
- 当前激活项继续保留高亮态，避免用户失去位置感

### 4. 菜单交互设计

#### 收起态下一级菜单无子项

- 点击图标后直接进行原有路由跳转

#### 收起态下一级菜单有子项

- 点击图标后，在侧栏右侧弹出浮层菜单
- 浮层中展示该一级菜单下的子菜单项
- 点击子菜单项后执行原有跳转逻辑，并关闭浮层

交互边界：

- 展开态不改变现有子菜单行为
- 收起态只改变“子菜单显示载体”，不改变菜单数据内容
- 不在收起态保留树状展开结构，避免窄栏里堆特殊情况

### 5. 视觉与样式设计

#### 尺寸

- 展开态侧栏：保持当前视觉比例
- 收起态侧栏：`56px`
- 弹层菜单：宽度独立，不受窄侧栏限制

#### 激活态

- 展开态沿用现有蓝色激活样式
- 收起态继续保留明确的当前项高亮
- 激活反馈可延续左侧蓝条或蓝底，但必须保证图标居中时仍然稳定可见

#### 过渡

- 仅增加轻量宽度和内容显隐过渡
- 不引入复杂动画，不追求炫技
- 优先保证切换稳定、无抖动

#### 样式约束

重点检查 `Layout.vue:216` 之后的这批深度样式：

- `.t-menu__item`
- `.t-submenu__title`
- `.t-menu__sub`
- `.t-fake-arrow`
- `.t-is-active`

因为这些规则当前默认建立在“有文字、有箭头、有子级缩进”的前提下，收起后必须让规则在两种状态下都自洽。

### 6. 数据与兼容性边界

本次不改以下内容：

- 不改 `transformRoutesToMenus()` 输出结构
- 不改 `findMenuValueByPath()`
- 不改 `activeValue` 计算逻辑
- 不改 `tabsStore.syncRoute()`、`handleTabChange()`、`handleCloseTab()`
- 不改路由定义与页面组件

原因：

- 当前问题是布局表现问题
- 路由、tab、菜单数据流已经能工作
- 没必要为了一个 UI 收缩功能去扩散修改面

### 7. 风险与处理原则

#### 风险 1：收起态激活样式偏移

原因：当前激活样式依赖文字行高和左侧蓝条定位。

处理原则：

- 把激活态样式调整为同时适配展开态和图标居中态
- 不依赖文字节点尺寸作为唯一定位基础

#### 风险 2：子菜单弹层被裁切

原因：父级容器存在 `overflow-hidden` / `overflow-x-hidden` 约束。

处理原则：

- 弹层应挂载到不会被窄栏裁切的位置
- 避免弹层被内容区或侧栏滚动容器截断

#### 风险 3：图标与 hover 热区错位

原因：当前 `.t-menu__content`、gap、padding 都偏向展开态设计。

处理原则：

- 收起态下单独约束菜单项对齐和居中
- 保证点击区域足够大，不做仅图标可点的小热区
