# ERP 风格侧边菜单样式设计

**目标：** 在不改动页面整体壳层、不改动路由与菜单数据结构的前提下，将左侧菜单视觉调整为传统 ERP 后台风格：窄侧栏、白底、一级项更高更疏朗、二级项缩进清晰、选中项使用浅蓝背景块。

**范围：** 仅调整 `niro-client/src/components/Layout.vue` 中的侧栏宽度与菜单局部样式；`SidebarItem.vue` 保持现有递归结构，不新增状态和交互逻辑。

**约束：**
- 不改顶部 header。
- 展开态宽度改为更窄的 ERP 风格宽度。
- 折叠态继续使用 TDesign 官方 `popup` 行为。
- 不重写菜单系统，不修改菜单数据、权限和路由跳转。

---

## 方案对比

### 方案 1：纯样式收口，保留现有递归结构
直接调整 `Layout.vue` 中的 `t-aside` 宽度、`t-menu` 宽度，以及 `:deep(...)` 菜单样式，控制菜单高度、字体、图标、缩进、hover 和选中态。

**优点：** 改动最小，风险最低，和当前实现最兼容。
**缺点：** 只能做到高度接近目标图，不能保证逐像素一致。

### 方案 2：样式收口 + 微调节点结构
在方案 1 基础上，顺手微调 `SidebarItem.vue` 的 submenu 节点结构，让父子层级的标题区域更贴近参考图。

**优点：** 视觉更容易贴近目标图。
**缺点：** 会扩大改动面，影响递归菜单结构，收益不高。

### 方案 3：重做菜单壳层
绕开当前 TDesign 菜单结构，重写一层自定义侧边导航。

**优点：** 可完全定制视觉。
**缺点：** 明显过度设计，会破坏现有官方折叠与 popup 能力，不符合最小修改原则。

**结论：** 采用方案 1。

---

## 设计决策

### 1. 侧栏宽度
- 展开态收紧到约 `180px ~ 200px`。
- 折叠态继续保持 `64px`。
- 宽度变窄后，通过样式收口保证文字仍可读，而不是继续依赖大留白布局。

### 2. 菜单项视觉
- 一级菜单项高度调整到约 `46px ~ 50px`。
- 一级菜单字体维持在 `15px` 左右。
- 图标尺寸控制在 `18px` 左右，避免图标占位过大。
- 菜单组之间保持规整间距，整体更像传统 ERP 导航，而不是卡片式导航。

### 3. 层级与选中态
- 二级菜单缩进清晰，但不做过深嵌套，避免中文标题过早被压缩。
- 当前选中项改为“整块浅蓝背景 + 蓝字”的高亮方式。
- hover 态只保留轻量浅灰蓝背景，不再使用重视觉激活条作为主识别方式。

### 4. 兼容性策略
- 不修改 `SidebarItem.vue` 的递归逻辑。
- 不修改路由跳转逻辑。
- 不修改菜单数据映射。
- 折叠态继续依赖 TDesign `collapsed` + `expand-type="popup"`。

## 风险与控制

**风险：** TDesign 内部类名样式覆盖过多，后续升级时可能发生偏移。

**控制方式：**
- 只在 `.erp-side-menu` 作用域下覆盖局部类名。
- 不修改 Header、Tabs、Content 区域样式。
- 不新增额外菜单状态。

---

## 验证方式

- 人工核对展开态菜单是否接近目标图。
- 验证折叠态是否仍只显示图标并正常弹出子菜单。
- 运行 `pnpm type-check`。
- 运行 `pnpm build`。
