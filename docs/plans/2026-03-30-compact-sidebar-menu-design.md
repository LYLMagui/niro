# 紧凑型侧边菜单设计

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 将左侧菜单调整为紧凑模式，优先使用 TDesign 官方菜单能力，解决内边距过大、图标过大、多级菜单显示不全的问题。

**架构：** 保留现有 `Layout.vue` + `SidebarItem.vue` 的菜单递归结构，不重写菜单系统。优先依赖 TDesign Vue Next 的 `collapsed`、`width`、`expand-type` 等官方能力控制展开与折叠行为，再对官方未暴露的间距、图标尺寸、层级缩进做最小样式覆盖。展开态保证多级菜单内联显示，折叠态保持一级图标并通过 popup 展示子菜单。

**技术栈：** Vue 3、TypeScript、TDesign Vue Next、Tailwind CSS

---

## 设计背景

当前侧边菜单存在两个根因问题：

- 默认菜单项的左右留白偏大，`Layout.vue` 里还有额外的 `.t-menu__content` 左边距，导致有效文字区域过窄。
- 图标尺寸和图标占位偏大，多级菜单缩进叠加后，中文标题在展开态也容易被过早截断。

这不是路由或菜单数据问题，而是菜单密度配置问题。正确做法不是重写菜单，而是把 TDesign 菜单调回更适合后台场景的紧凑密度。

## 设计决策

### 1. 宽度策略

- 展开态侧栏宽度调整为 **168 px** 左右。
- 折叠态侧栏宽度保持 **64 px**。
- 不通过无限加宽掩盖问题，而是同时压缩菜单项 padding、图标尺寸和层级缩进。

### 2. 交互策略

- **展开态：** 一级、二级、三级菜单继续在侧栏内联展开。
- **折叠态：** 只显示一级图标，子菜单使用 TDesign 官方 `popup` 行为展开。
- **选中态：** 保留蓝色高亮背景和左侧激活条，但收细激活条宽度与上下留白，使其适配紧凑布局。

### 3. 样式策略

- 优先使用 TDesign 官方属性：`collapsed`、`width`、`expand-type`。
- Tailwind CSS 只用于外层布局尺寸和间距控制。
- 对官方类名的深层样式，仅在以下场景做最小覆盖：
  - 菜单项高度
  - 左右内边距
  - 图标尺寸与图标占位宽度
  - 多级菜单缩进
  - 箭头图标与激活条尺寸
- 不新增独立菜单样式系统，不重写 `SidebarItem.vue` 的递归渲染逻辑。

## 受影响文件

### 修改文件

- `niro-client/src/components/Layout.vue`
  - 调整侧栏宽度和 `t-menu` 属性。
  - 收敛深层菜单样式，改为紧凑布局。
- `niro-client/src/components/SidebarItem.vue`
  - 只在必要时保持最小菜单节点结构，不引入新的折叠逻辑。

### 不修改文件

- `niro-client/src/utils/menu.ts`
- `niro-client/src/store/permission.ts`
- 路由与权限配置相关文件

## 验收标准

- 展开态侧栏宽度控制在约 **168 px**。
- 菜单项内边距明显缩小，视觉密度接近参考图。
- 图标尺寸明显减小，不再挤占标题区域。
- 二级及三级菜单在展开态下正常显示，不因缩进和图标导致大面积截断。
- 折叠态只显示图标，子菜单通过 TDesign 官方 popup 正常展开。
- 优先使用官方组件属性，仅在必要处做局部覆盖。
- 样式实现以 Tailwind CSS + `:deep(...)` 最小覆盖为主。

## 风险与兼容性

- **风险：** 过度覆盖 TDesign 内部类名，可能导致后续升级样式偏移。
- **控制方式：** 只覆盖当前菜单路径下的局部类名，避免影响 Tabs、Header 等其他区域。
- **兼容性：** 不改菜单数据结构，不改路由映射，不改点击与选中逻辑，因此行为兼容性风险较低。

## 验证方式

- 人工验证展开态和折叠态菜单显示。
- 运行 `pnpm type-check` 确认类型无破坏。
- 运行 `pnpm build` 确认生产构建无破坏。
