# Niro Simple 简化版设计

日期：2026-03-26
分支：`niro-simple`

## 1. 目标

在 `niro-simple` 分支上产出一个简化版本：

- 删除整个 `niro-spider`
- 移除 RocketMQ
- 移除 XXL-JOB
- 保留前端 + Spring Boot 后端的双层架构
- 前后端中依赖这些能力的页面、接口、配置一并收敛
- 尽量保留兼容壳子，避免直接把现有页面和接口全部砍掉

这个版本的核心目标不是做新功能，而是把系统从“前端 + 后端 + 爬虫 + MQ + 调度”的多模块形态，收敛成一个更容易部署和维护的简化版。

---

## 2. 目标架构

简化后架构：

```text
Frontend (Vue) <-> Backend (Spring Boot)
```

移除链路：

- `niro-spider` 模块
- Backend 到 Spider 的联动
- RocketMQ 消息生产与消费链路
- XXL-JOB 调度链路

保留链路：

- 前端管理台
- Spring Boot 核心 API
- 后端对数据库 / Redis 的直接业务处理

原则：

1. 不为了“看起来完整”保留已经失效的异步链路。
2. 不引入新架构补丁，仍然维持现有前后端分层。
3. 优先做收敛，而不是做新的替代系统。

---

## 3. 模块处理策略

### 3.1 后端

保留：

- `niro-core`
- `niro-web` 中与基础业务、系统管理、普通 CRUD 相关的 controller / service / mapper

移除或下线：

- `mq/` 下 RocketMQ 相关生产者、消费者、配置
- `jobhandler/` 下 XXL-JOB 执行器与配置
- 与爬虫任务投递、状态回流、异步消费强绑定的 service 逻辑
- `docker/` 中 RocketMQ、XXL-JOB 相关部署文件

处理原则：

- 纯业务接口保留
- 部分依赖 MQ / 调度 / Spider 的接口，收敛为同步或简化逻辑
- 完全依赖 Spider / MQ / 调度的接口，优先保留路由壳子，再返回明确的“简化版不支持”或空结果
- 继续遵守 Controller-Service-Mapper 三层边界，不在 Controller 中堆业务逻辑

### 3.2 前端

保留：

- 能独立运行的页面
- 与后端普通 CRUD、配置展示、系统管理相关的页面结构

移除：

- 页面中依赖爬虫执行、任务下发、异步状态轮询、调度配置的组件
- RocketMQ / XXL-JOB / Spider 相关表单项、按钮、tab、提示文案

处理原则：

- 整页尽量保留
- 删除不能工作的局部组件和操作区
- 页面要么保留剩余可工作部分，要么呈现简化后的空状态
- 不保留假按钮、失效操作入口和点了必报错的交互

### 3.3 Python

直接移除：

- `niro-spider/` 整个模块
- 根文档、脚本、配置中对 Spider 的启动说明与依赖引用

---

## 4. 兼容性策略

### 4.1 后端接口

分三类处理：

1. **完全独立的接口**
   - 保留，行为不变

2. **部分依赖异步链路的接口**
   - 保留接口与 DTO
   - 去掉 RocketMQ / XXL-JOB / Spider 相关字段和分支
   - 若剩余能力仍成立，则改为同步或本地简化逻辑

3. **完全依赖 Spider / MQ / 调度的接口**
   - 优先保留路由壳子
   - 返回明确的“简化版不支持”或空数据
   - 避免旧前端因为接口直接消失而报错崩掉

### 4.2 前端页面

分三类处理：

1. **页面主体仍有价值**
   - 保留页面
   - 删除任务调度、异步执行、抓取配置、队列状态等组件
   - 剩余部分继续正常工作

2. **页面大部分依赖已移除能力**
   - 保留页面壳子
   - 显示空状态或简化提示
   - 不显示已失效按钮和配置项

3. **纯依赖型页面**
   - 直接从菜单和路由移除
   - 不为了兼容保留没有实际价值的空页面

核心判断：保留的是还有业务价值的页面，不是机械保留所有旧页面。

---

## 5. 风险与约束

最大风险不在“删目录”，而在“残留依赖没有清干净”。

重点风险：

- 后端仍有隐藏的 MQ / XXL-JOB / Spider 依赖
- 前端页面仍在调用旧接口或渲染旧配置块
- 菜单、路由、枚举、状态字段和环境配置残留，导致编译或运行失败
- 文档与真实行为继续漂移

约束：

- 最小修改，优先沿着依赖链清理
- 不做无关重构
- 不为一次性兼容需求引入额外抽象
- 保持前端与后端的既有边界清晰

---

## 6. 验收标准

### 后端

- 不再依赖 RocketMQ
- 不再依赖 XXL-JOB
- 不再依赖 `niro-spider`
- Spring Boot 可以正常编译启动
- 相关接口要么正常工作，要么明确返回“简化版不支持/空结果”，不能留下 500

### 前端

- 可以正常编译
- 保留下来的页面可以正常打开
- 已移除能力对应的组件、按钮、配置块不再出现
- 不出现明显死按钮、失效操作入口、空白报错页

### 仓库

- 删除 `niro-spider/`
- 清理 `docker/`、文档、配置中的 RocketMQ、XXL-JOB、Python 相关说明
- 仓库对外表现为“前端 + Spring Boot”的简化版

---

## 7. 实施原则

实施顺序应优先按依赖链进行，而不是按目录机械删除：

1. 先识别后端 RocketMQ / XXL-JOB / Spider 的直接依赖点
2. 再处理这些依赖对应的接口与服务
3. 然后收前端页面、组件、菜单和路由
4. 最后删除模块、部署文件与文档残留

这样做的目的，是避免删得太快却留下无法编译、无法启动、无法访问的半残状态。
