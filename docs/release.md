# Release Notes

- [安全] **增强任务管理系统的权限校验与数据隔离**
  - **数据隔离**：重构后端任务分页查询逻辑，普通用户仅能查看并操作自己创建的任务，管理员（UID=1）保留全局查看权限。
  - **权限控制**：

  - **前端适配**：
    - 登录流程优化，成功后在本地存储持久化用户信息。
    - 任务配置界面根据当前用户角色动态展示 UI，非管理员用户自动隐藏系统任务相关选项。

## v1.16.32 (2026-01-13)
- [优化] **商品同步状态追踪逻辑增强**
  - **DB 实存校验**：商品同步完成后，不再直接拿接口返回的 `total_count` 缓存至 Redis，改为从数据库中查询当前分类的实际商品总数进行缓存。这解决了因网络丢包或去重导致库中实际数量与接口数量不一致，从而影响下次同步判断的问题。
  - **简化对比逻辑**：移除了同步状态中的 `total_page` 对比，仅保留 `total_count` 作为同步决策的唯一指标，提升了逻辑的健壮性。
- [修复] **移除冗余依赖与代码逻辑修复**
  - **解耦 Numpy**：在 `network_util.py` 中使用 Python 标准库 `random.gauss` 替代 `numpy.random.normal`，移除了对大型库 Numpy 的不必要依赖。
  - **修复 NameError**：删除了 `get_buff_goods.py` 中引用未定义变量 `mu` 和 `sigma` 的调试日志行。
  - **逻辑闭环**：修复了 `get_buff_goods.py` 中循环体逻辑因缩进问题导致的风控逻辑失效错误。

## v1.16.31 (2026-01-13)
- [优化] **工业级高级风控对抗方案升级**
  - **正态分布延迟 (Gaussian Delay)**：引入基于正态分布的智能延迟工具函数 `smart_sleep`。模拟人类行为，使请求间隔更多集中在均值附近，极少数情况出现极端长或短的延迟，有效规避基于固定或均匀分布规律的频率检测。
  - **分段延迟策略 (Segmented Delay)**：针对不同类型的 API 请求实施差异化延迟方案。首页 Metadata 获取采用较短延迟 (均值 3s)，而数据翻页请求采用较长延迟 (均值 15s)，模拟真人浏览行为习惯。
  - **长时休眠模式 (Coffee Break)**：新增“喝咖啡”长休眠逻辑。每连续采集 50 页商品后，随机进入 3-7 分钟的深度休眠状态，并自动刷新代理 IP，彻底打破高频采集的指纹特征。
  - **代理 IP 预热刷新**：在长休眠结束后自动执行代理节点切换，确保恢复抓取时使用的是全新的 IP 节点，提升链路安全性。

## v1.16.30 (2026-01-13)
- [优化] **商品抓取分页稳定性深度调优**
  - **显式排序机制**：在所有商品列表请求（含全量抓取与分类同步）中，强制引入 `sort_by=price.asc`（按价格升序）参数。
  - **解决数据漂移**：通过对比测试验证，显式排序有效解决了 BUFF 默认排序下由于分页不稳定导致的商品“漂移”与遗漏问题（实测单分类漏抓率降低约 25%）。
  - **提升数据完整性**：确保在大规模全量同步过程中，分页边界的数据能够被稳定覆盖，显著提升了饰品入库的完整度。

## v1.16.14 (2026-01-12)
- [功能] **分类级同步状态追踪与智能差异同步**
  - **Redis 状态持久化**：引入分类状态追踪机制，在 Redis 中持久化存储每个分类 of 商品总数 (`total_count`) 和总页数 (`total_page`)。
  - **智能同步决策**：
    - **等量跳过**：若当前 Buff 数量与 Redis 记录一致，自动跳过该分类，极大提升二次同步效率。
    - **缩减重刷**：若当前数量少于记录值（意味着大量下架或数据异常），自动清空数据库中该分类的所有旧数据并执行全量拉取。
    - **增量 UPSERT**：若数量增加，则执行正常同步，利用 UPSERT 机制完成新饰品的插入与旧饰品的更新。
  - **数据一致性保障**：新增 `delete_category_goods` 辅助函数，确保在数据缩减场景下能彻底清除脏数据。
