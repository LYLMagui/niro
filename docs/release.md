# Release Notes

## 2026-01-19 (v2.4.1)
- **爬虫数据同步健壮性修复**:
  - **SQLAlchemy 导入修复**: 修复了 `get_buff_goods_category.py` 中缺失 `sqlalchemy.func` 导入的问题，解决了分类同步任务在执行 UPSERT 操作（更新 `update_time`）时因 `NameError` 导致的任务中断。
- **后端 Redis 序列化异常修复**:
  - **跨语言序列化兼容**: 修复了 `BuffScanTaskServiceImpl` 在自愈逻辑中读取 Python 写入的 JSON 进度时，因 Jackson 缺少类型标识 (`@class`) 导致的 `SerializationException`。
  - **RedisUtil 增强**: `RedisUtil` 引入 `StringRedisTemplate`，优化 `getToString` 方法以支持纯字符串/跨语言 JSON 数据的无损读取。

## 2026-01-19 (v2.4.0)
- **基础数据分片采集与多账号协同重构**:
  - **后端 Java：分片下发与自愈守护**:
    - **Payload 结构升级**: 任务下发 Payload 现包含绑定的所有 NORMAL 账号列表、用户 ID 及分类分片 ID 列表。
    - **自愈守护 (Self-Healing)**: 实现 `CategoryTaskMonitor`，周期性检查运行中任务的 Redis 心跳，支持 Redis 宕机或 Python 崩溃后的断点续传与重平衡。
    - **账号动态注入**: 下发任务前强制过滤非 NORMAL 状态账号，确保执行效率。
  - **Python 协同执行器：异步分片执行**:
    - **ShardedSpiderExecutor**: 基于 `asyncio` 实现的全新执行器，支持分类/商品同步任务的动态分片映射与异步执行。
    - **频率控制与隔离上下文**: 集成 `aiolimiter` 实现账号级 QPS 限制，利用 `contextvars` 确保请求上下文严格隔离，日志输出包含账号标识。
    - **动态剔除逻辑**: 自动捕获 401/429 异常，实时调用 API 更新后端账号状态，并触发任务重平衡。
  - **存储层优化：幂等写入与冲突处理**:
    - **Upsert 机制**: 重构 `category` 与 `goods` 写入逻辑，采用 PostgreSQL `INSERT ... ON CONFLICT` 语法，解决并发冲突。
    - **分布式状态锁**: 在分类树与商品同步入库时引入 Redis 锁，防止多账号同时更新同一分类节点导致的数据不一致。
  - **实时监控：TPS 与 任务进度可视化**:
    - **状态实时反馈**: Python 端异步更新任务整体进度、TPS 及各账号独立进度至 Redis。
    - **前端可视化看板**: `TaskProgressCard` 组件重构，新增“分片进度条”与实时 TPS 监控面板，支持多账号执行进度可视化展示。

## 2026-01-18 (v2.3.5)
- **任务弹窗交互与布局深度优化**:
  - **校验逻辑精准修复**: 彻底解决打开任务弹窗时立即触发必填项（尤其是执行账号）报错的问题。通过为各表单项明确配置 `trigger: 'blur'` 或 `trigger: 'change'`，配合 `validation-trigger="blur"` 与 `clearValidate()`，确保弹窗初始状态纯净，仅在失焦或提交时触发校验。
  - **调度配置交互升级**: 新增“立即执行”与“不限时间”复选框，选中后自动禁用并清理对应的 Cron 表达式与持续时间，支持双向状态切换，大幅精简界面文案。
  - **动态布局自适应**: 深度调优 CSS，将报错文案强制设为相对定位 (`relative`)。现在当报错信息出现时，它会准确占据文档流空间，自动顶开下方元素，完全解决了 UI 堆叠覆盖 BUG。
- **任务编辑体验优化**:
  - **账号回显修复**: 修复了编辑任务时，执行账号在初始加载时显示为原始 ID（如 1,2）而非账号名称的问题。通过在弹窗打开时提前预加载账号列表，确保下拉框能够即时完成 ID 到名称的映射。
- **后端服务健壮性增强**:
  - **空指针异常 (NPE) 深度治理**: 针对 `/buff/account/list` 接口中由于 `Collectors.toMap` 遇到 null 值、缺失 `Schema` 导入以及 `BeanUtil` 反射实例化不确定性导致的 NPE 进行了彻底重构。现在采用防御性编程方式手动构建 Map，并强化了 DTO 的类型安全。
