# Release Notes

## v1.16.25 (2026-01-13)
- [修复] **解决商品批量保存时的数据库冲突错误**
  - **去重逻辑优化**：修复了在 `save_goods_batch` 过程中，由于 Buff API 返回重复商品导致 PostgreSQL 触发 `CardinalityViolation` 错误的问题。
  - **内存级去重**：在执行 `UPSERT` 操作前，通过 Python 字典对 `goods_id` 进行内存级去重，确保每个原子操作中同一行只被更新一次。

## v1.16.23 (2026-01-12)
- [验证] **完成 Clash 节点切换功能实测验证**
  - **实测成功**：通过 `test_clash.py` 脚本成功验证了节点从 `[美国03]` 切换至 `[美国04]`，出口 IP 从 `23.94.213.251` 变更为 `104.153.208.166`。

## v1.16.22 (2026-01-12)
- [优化] **引入工业级指数退避与随机抖动 (Jitter) 重试策略**
  - **抗惊群效应**：采用 `wait_random_exponential` 策略，在指数级增加等待时间的基础上引入随机偏移，有效打散并发重试请求，降低二次触发限流的概率。
  - **风控穿透增强**：结合 Clash 自动切线机制，在每次指数级等待的间隙完成 IP 更换，实现“时间+空间”维度的双重风控穿透。
  - **统一重试规范**：将该策略应用至商品列表抓取、自动下单等所有核心业务链路，默认重试次数统一为 3 次。

## v1.16.21 (2026-01-12)

## v1.16.14 (2026-01-12)
- [功能] **分类级同步状态追踪与智能差异同步**
  - **Redis 状态持久化**：引入分类状态追踪机制，在 Redis 中持久化存储每个分类的商品总数 (`total_count`) 和总页数 (`total_page`)。
  - **智能同步决策**：
    - **等量跳过**：若当前 Buff 数量与 Redis 记录一致，自动跳过该分类，极大提升二次同步效率。
    - **缩减重刷**：若当前数量少于记录值（意味着大量下架或数据异常），自动清空数据库中该分类的所有旧数据并执行全量拉取。
    - **增量 UPSERT**：若数量增加，则执行正常同步，利用 UPSERT 机制完成新饰品的插入与旧饰品的更新。
  - **数据一致性保障**：新增 `delete_category_goods` 辅助函数，确保在数据缩减场景下能彻底清除脏数据。

## v1.16.5 (2026-01-12)
- [修复] **分类抓取 parent_id 关联失败问题**
  - **问题定位**：在 `save_categories` 函数中，二级分类的 `parent_id` 字段始终为 0，导致分类层级混乱。经排查发现，API 返回的 `parent_internal_name` 带有 `csgo_type_` 或 `type_` 前缀（如 `csgo_type_knife`），而数据库中的一级分类 `internal_name` 为纯名称（如 `knife`），导致名称匹配失败。
  - **修复方案**：在 `get_buff_goods_category.py` 中新增 `normalize_internal_name` 规范化函数，在构建映射表时自动去掉 `csgo_type_`、`type_`、`csgo_` 等前缀，确保父子分类能正确关联。
